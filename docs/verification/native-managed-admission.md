# Managed startup preserves installed editor routing

The managed admission refresh used to retire the view, storage and undo routing
that genuine document startup had just installed. Two actual-owner regressions
reached sixteen missing-association assertions before the correction. This
repair keeps an eligible current installation and still retires revoked
membership. It never creates a replacement route as admission.

The original call captures remain authoritative after callback-bearing endpoint,
window, document and presentation calls. A callback-created valid successor can
survive while the older call refuses; a genuine close ticket revokes editing and
retires its associations. Current-state cleanup runs on exits after established
membership. The earliest endpoint-validation refusal preserves its prior behavior.

## Implementation and review

The production change is confined to `EditorWindowController.swift`: a
callback-free current-routing predicate and the managed admission refresh.
The formatted candidate is 317,754 bytes, SHA256
`6189b02e6eed429290d64df368ab667e052fa85715ebe354492930702ade55a7`.
Independent source, formatting and actual-result reviews accepted this bounded
scope. No private custom-language owner, highlighter, manager, comment editing or
selection-history candidate is included.

The original 32 routing tests remain byte-exact. Two additive callback cases and
two startup cases use real process owners, models and synthetic files. Declaring
access tails expose stored associations and reuse the original disk-conflict
construction forwarder; the latter is explicitly not read-only. They do not
install routing, warm history or replace admission. The archive-compatible
runner freezes the full dependency graph, appends only declared access and owns
its watchdog directly. Never wrap it in another process-group watchdog.
