# Custom language catalog inspection

The Core store now offers bounded, read-only inspection before a language manager decides which recovery actions are available. This is a tested component, not completion of custom-language management or editing integration.

`inspect()` returns a genuine loaded catalog, a known-format corruption inspection, or an unsupported-format inspection. It preserves raw bytes and never writes, changes permissions, or resets a catalog. A corruption inspection has no public or memberwise constructor; it binds the original owned stable read, destination, parent identity and full leaf metadata. Repair and publication retry are still outstanding.

The classifier walks every recognized schema position before strict decoding. Unknown root or nested fields, versions, variant kinds, built-in language identifiers and ambiguous containers prevent a repair token, even when another known field is invalid. Noncanonical version spellings also remain unsupported. Parser-invalid or duplicate-key input is conservatively preserved as unsupported; explicit malformed-format export/replacement requires a separate recovery workflow. Unsafe endpoints, read races, and byte/depth/work limits throw rather than grant replacement authority.

Original `load()` and `save()` source remains unchanged. Inspection uses a separate owned descriptor reader with the original bounded read and stable-file checks. It accepts only the existing same-owner, mode-0700 directory and single-link regular mode-0400/0600 leaf, with a 1 MiB limit. A read-only leaf can be inspected; this does not authorize a write. Parsing has depth-16 and 100,000-value limits, with the current profile and field budgets preserved.

## Verification

Five new tests use synthetic real temporary files. They cover valid/missing/known-invalid catalogs, future and noncanonical versions, unknown sibling metadata, nested schema fields and policy discriminators. Actual reads occur off the main thread; bytes, leaf/parent metadata and directory membership are preserved. The nonworking load-only baseline reached five genuine strict-decoder errors after real reads. Those historical errors were retained; later unreachable variants were not credited as tested.

The accepting unformatted source passed the five tests and a separate 35-test conjunction including all 30 existing store/codec/revision/readback cases. The formatted application candidate passed **1,164 unique tests, zero failures, unexpected errors or skips**. Its cold test dependency build compiled and linked the actual app and search helper with warnings treated as errors in 15.42 seconds. The following build used the same scratch directory and was incremental confirmation (reported 0.23 seconds; owned-process elapsed time 0.556224 seconds), not another fresh build. Its only production change was the inspection addition; the five-test file was added without changing existing tests. Independent source review and independent full-run audit accepted this scope. The audit verified all 485 input bindings, 297 objects (296 authored sources plus the generated runner), 36 module companions, exact app/helper/test link inputs, current binaries, and both complete owned-process receipts. The full test run completed naturally with exit zero in 39.36328 seconds; the following incremental build also completed naturally with exit zero.

Raw diagnostics, source inventories and synthetic fixtures remain ignored locally. No real documents or credentials were used. Runtime verification was ARM64 macOS 26.6.2 with Swift 6.3.3 in Swift 5 language mode; the declared deployment target remains macOS 14. Intel and macOS 14 execution were not performed.

Native custom-language propagation/highlighting candidates, catalog-owner activation, repair/evidence recovery, native editing policy, the manager and picker, and new desktop/performance acceptance remain separate work. The previously verified packaged five-workflow checkpoint is unchanged by this Core-only source addition; this addition has not yet been packaged or exercised through a manager UI.
