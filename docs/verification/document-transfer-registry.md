# Registry transfer slice verification

Implemented: existing-window, single-group transfer reservation, staging, rollback and settlement for the same active editable handle. Native projection, monitor ownership transition, process pause/quit integration, new windows, independent groups, streaming and desktop acceptance remain separate work.

The registry owns both ownership rotations. Staging/rollback do not publish partial placement. Final settlement invokes trusted process settlement while public reentry remains fenced, then publishes one revision/notification. Recovery authority and issuance fence remain unchanged. Rotation uses a dedicated nonthrowing collaborator returning the exact freshly minted ownership/mutation pair. The registry constructs expected state from that pair before any throwing read. Transient post-rotation read failure retains its gate and known tokens: staged retry does not rotate twice, and rollback has already coherently restored placement before its post-read. Arbitrary other scalar mutation or invalid returned tokens remain unsafe; expectations are never refreshed from a later model read. Effect-free cancellation preserves unrelated model changes.

`transferSnapshot(lease)` is diagnostic only. It exposes `effectsStarted`, `requiresReconciliation`, original/current window snapshots and captured expected state. `validateTransferSnapshot(lease)` is the authorization boundary and refuses stale/unsafe scalar state. A snapshot value alone never enables ordinary admission. Callers must finish restoring any pre-stage native effects before canceling an unstaged reservation.

Command: `scripts/test-document-transfer-registry.sh`. It snapshots PadCore, actual registry/recovery source and the unchanged registry/adoption/history/close test files into a private package, with source hashes and a 180-second owned-child watchdog. Existing explicit-source runner lists gained only the new boundary dependency.
