# Presentation refresh and pending outcomes

Status: implemented and hidden-tested; actual desktop interaction remains unverified.

A bounded variant review followed the shortcut editor's notification-generation bug. The exact original pattern matched its retained failing source; the literal identifier had no production counterpart. Generalized review examined15 native async sites. Thirteen were rejected because they invalidate only for a new request, cancellation, changed target or close. Two presentation-call-site candidates were then reproduced with actual controllers: raising an unchanged Recent Files or Session panel could suppress a pending result/error by invoking its explicit cancellation API. File-preservation assertions continued to pass; this was not a demonstrated data-loss bug.

The existing `update` API intentionally invalidates requests and remains unchanged. New `refreshPresentation` methods preserve active work only when its selected target is still current. Recent Files compares the selected path, preserves it across unrelated list reorder and suppresses selection callbacks only during programmatic restoration. A real selection change, target removal, suspension or close still cancels. Session restoration compares record/window identity, complete metadata and recovery availability; a changed target cancels while status-only or unrelated-record updates can preserve the pending outcome. AppDelegate uses presentation refresh when raising panels or reporting MRU changes and retains explicit `update` for quit fencing.

Independent source review found no material regression. Original same-refresh reproductions failed while no-refresh controls passed. The first fix's red suite retained explicit-invalidation controls, and the final success expansion added exact successful open/resolution/removal assertions. `scripts/test-native-presentation-refresh.sh .build/shortcut-native-integration/arm64-apple-macosx/debug` passed26 child scenarios and163 assertions in `.local/presentation-refresh-tests/run.XW0PSbtU`; all children exited0 and the compiler log was empty. Original failures and search triage remain ignored under `.local/shortcut-variant-review`.

The retained runner snapshots/hashes production controllers and linked PadCore objects. It appends explicit test-access extensions and substitutes exactly one count-guarded removal-confirmation boundary in the private test copy. The actual async removal branch remains unchanged; positive confirmation is injected without showing a sheet. No window is shown or activated. This does not prove real confirmation ordering, accessibility or AppDelegate desktop invocation. Existing visible Recent/Session harnesses have not been rerun while GUI access is blocked.

The meaningful regression rule is behavioral: a cosmetic refresh must preserve a current request's outcome; an actual target or lifecycle invalidation must reject it. CI runs both positive and negative cases through the retained script. A blanket prohibition on generation guards would break valid cancellation and is not used.
