# Managed session publisher

Status: publisher component implemented; 18 isolated real-store tests pass, and frozen native application compilation passes. Independent final review pending. AppDelegate activation, controller managed capture/drain adapters, and native close/intake wiring remain planned. Existing AppDelegate initializer retains legacy behavior.

The application has one SessionCheckpointCoordinator timer and one RecoveryCoordinator paired writer. A managed publisher starts stopped, coalesces requests, and cannot publish until an exact owned activation has drained and all registry documents are actively adopted. Startup intake can acquire its own pause only through acquireActivationPause with that exact outer activation; finish refuses outstanding inner holds. An empty live set still requires intake, close, session, and projection readiness. Actor adoption receipts and retry progress belong solely to the intake owner; its settlement callback excludes the publisher's own activation token.

Activation is a publication barrier, not atomic rollback of multiple actor adoptions. Failure retains its token and visible error, without offering an ineffective checkpoint retry; intake owns the real retry action. The same activation can finish after intake repairs its own state. Activation requires completed restoration but not valid saved metadata: verified recovery-only scratch imports can become usable while the original metadata remains preserved. Actual capture still refuses every publication under that metadata error. Managed publication never falls back to legacy writes. Application controllers must separately freeze and drain every legacy submission before adoption; presence of onSessionChange alone is not that guarantee.

Capture runs synchronously on MainActor. Registry placement owns tab order, selection, and pins; native capture supplies exact model text/disposition and pane state. Capture rejects inactive records, unrepresentable multiple groups, changed registry revision/projection, duplicate or missing live recovery items, and nil/wrong-document/wrong-actor authority. Native validation must check exact handle identity and every app endpoint against registry ownership, and preflight the 100M UTF-16 resource budget before copying snapshots. The actor independently enforces authority and resource admission. Existing SessionCoordinator preserves unresolved entries, recents, pending cleanup checks, and corrupt/future session refusal. No unresolved entry receives a fabricated live authority.

The native capture adapter returns immutable authority captured with the bytes. Commit never re-reads live model authority. Managed captures, including zero-document captures, call commitAuthorizedSessionCheckpoint. Uncertain publication validation only permits a new write; the actual actor receipt is the sole acknowledgement.

Close/adoption pause acquisition forwards exact owned scheduler tokens and refuses quit/final phases. Release cannot consume the activation token or another owner's token. Managed prepare synchronously checks intake/close admission before and after independent session-removal draining. It must never await the process close owner: that owner is draining this publisher. Native legacy pending-close draining belongs before activation; an unexpected later legacy close is an admission failure.

Quit transitions managed → preparingQuit after synchronous settlement checks and through the existing legacy scheduler pause/drain. markNativeQuitPrepared is accepted only after this drain and after the trusted caller freezes every native document. It enters finalReady; only commitFinal can enter finalizing, whose capture is explicitly permitted while ordinary capture stays blocked. Caller thaws native state before cancelPreparedQuit. Cancellation does not release independent close/adoption pauses. Final failure leaves finalReady for explicit retry/veto; publication requires a fresh real receipt.

The Foundation-only publisher core accepts real SessionCoordinator, ApplicationDocuments and RecoveryCoordinator dependencies. Native compatibility lives in ApplicationSessionCheckpoints+Native.swift and retains the existing initializer. No AppDelegate or EditorWindowController behavior is migrated by this component alone. Streaming viewer ownership and multi-group session schema remain separate work.
