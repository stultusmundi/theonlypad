# Native intake adapter implementation slice

This slice implements `NativeDocumentIntakeController` as the concrete bridge from EditorPreparedSubmission to ApplicationDocumentIntake, leaving endpoint table/AppDelegate ownership outside. It receives actual registry/session/recovery/publisher and required native endpoint callbacks (validate identity, require user admission, aggregate resource usage, drain legacy work, project exact registry, resolve selection). This avoids fake close callbacks or a second process registry/publisher. ApplicationDocumentIntake remains sole transaction state machine.

One retained Slot owns submission, exact created EditorDocument, process intake ID and current destination validation. `submit` synchronously validates endpoint, application admission, scalar/aggregate limits and absence of another slot, then retains the seed before starting intake. No factory before actual intake preflight. `makeHandle` uses EditorDocumentFactory and sets process-owned onCharactersChanged to publisher.requestCheckpoint. The model remains strongly held by intake/registry after registration. Slot is released only on terminal imported/refused; retained outcome keeps it. A process task owns wait/cleanup independently of caller lifetime; publication callbacks cannot make slot disappear while in use.

Native adapter closure verifies request seed ID/assignment matches Slot. `readState`/`install` use actual model capture/authority methods, no synthetic receipts. `resolveSelection` consults current endpoint/registry through required read-only callback after drains; process owner handles reentrancy fences. Resources sum actual native storage.length and originalBytes.count plus incoming precomputed scalars via SessionStartupBudget; no text scans in preflight.

Default destination check is the submitted exact endpoint check plus slot incarnation. Retained endpoint replacement requires explicit `reconcileDestination(intakeID, endpointID)` after old incarnation is absent, failed intake owns exact model in same assignment, new endpoint table identity validates, and current registry record equals the same model. This replaces only destination validation for this one retained Slot with new exact endpoint identity; submission provenance, assignment, source ID, model, lease and receipt remain unchanged. Original shouldAccept closure is consumed only for this explicit endpoint-loss reconciliation, never silently dropped for ordinary in-flight operations. Do not reconcile after terminal completion or to a different registry window/group.

Preparation/factory remains immutable and background-ready. No process Task.detached factory. Actual high-level process composition uses this adapter rather than duplicating closures in AppDelegate. Tests use actual native model, registry/actor/publisher and endpoint identities; include endpoint loss after adoption, installation refusal then same receipt retry, selection change during drain, active registry projection and fresh paired store read. Controller recreation/monitor hookup is tested when those adapters are ready; no desktop claims.

Reviewed refinements: destination validation repeats after projection; explicit endpoint reconciliation checks old-endpoint absence, unchanged registry revision, native adoption state and model assignment after callbacks. Prepared submissions may supply an insertion index; deriving the original session placement remains the process caller’s job. Endpoint/controller recreation and monitor attachment are outside this adapter and must be integrated before activation.
