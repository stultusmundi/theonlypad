# Process intake owner implementation contract

Reviewed Foundation implementation; native routing activation remains planned. The process uses the actual registry, session coordinator, recovery actor and publisher pause boundary.

One MainActor owner admits at most one payload-bearing intake at once. External file URL requests may queue separately but decoded seeds cannot: refuse busy before accepting a seed. This bounds duplicate source payload retention to one document plus the existing live budget. The request stores the immutable native seed via a factory closure and scalar resource counts; callbacks cannot replace its ID or metadata. The actual model remains strongly held across actor awaits, endpoint loss, cancelled waiters and failed installation.

The dependency boundary contains actual ApplicationDocuments, SessionCoordinator and RecoveryCoordinator; publication closures forward acquire/drain/release/request to the sole existing publisher. Native closures perform resource preflight, instantiate seed, install exact adoption receipt, read installed adoption state and project the exact registry assignment. No injectable adopt/commit/receipt source. Admission checks the application's startup/quit fence, and an endpoint incarnation captured independently of a source disk action. During startup, per-document readiness excludes the outer startup publication token.

Request provenance is an enum of fresh, ordinary SessionImportClaim or recovery-only SessionRecoveryImportClaim. Recovery-only source must use its immutable snapshot and URL-less native factory; other variants cannot clear preservationError. Fresh admission uses aggregate live+unresolved snapshot and refuses union growth above 32/128. Reserved admission calls the typed preflightImport, restores only original window, allows unchanged over-capacity union within live limits, and keeps publication blocked by actual SessionStore limits/preservation. Registry remains authoritative for group, live IDs, retired IDs and handle uniqueness.

Initial owner requires an already registered destination window/group. AppDelegate startup can register an empty endpoint from exact saved window ID before calling intake, but must not show or create a model beforehand. Failure may clean up only that still-empty exact endpoint; not arbitrary registry ownership. Document model factory is invoked only after capacity, destination/index and reserved-ID preflight. Add a registry read-only ID reservation query for this check (not an unregister or authority override). The process record exists before any callback, and holds a publication token before registration.

Stages:
1. Validate request/counts/provenance/destination without model creation; own record; acquire token before callbacks. Drain publisher and native legacy writes under application-wide admission freeze. Recheck source claim, destination incarnation and capacity after suspension.
2. Create exact model with no endpoint side effects. Store it before registration; validate id/kind/noauthority and resource observations. Call registerPending with current observed registry revision. Its callback sees pending state and the process record. If registration refuses before ownership, drain/release exact token and discard only this unregistered model. Callback-visible registration success cannot be treated as a failed unregistered model.
3. Call real actor adopt once; store result before any callback. On actor throw, retain registry pending/failed state and token. Explicit Retry invokes actor again only when no result was returned. On success, install the exact receipt on unchanged model. If readback already exactly matches a previously installed receipt after a throwing callback, don't rewind its revision. Activation uses matching current adoption lease and receipt; failure records exact registry failed lease.
4. If registry lease was marked failed, retryAdoption creates a fresh attempt before activation; do not call actor again if its receipt is retained. After registry active, never call activate/failAdoption again. Mark this stage before callbacks/reconciliation checks.
5. Resolve original typed claim only after exact active model ownership. If stale, retain active model+pause and explicit reconciliation: issue a new claim ONLY for same semantic retained entry and original window, not a generic arbitrary current record. A disappeared record requires diagnosis rather than silent duplicate publication. Record resolution before notification-capable projection. Fresh requests skip this stage.
6. Project exact destination. On failure retain model and retry only projection. Endpoint loss does not abandon model; a separate native endpoint recreation step may satisfy projection while preserving assignment. Only after projection and claim resolution release exact drained token and request checkpoint. Mark release before emitting terminal notification; release failure remains retained, no duplicate adoption or projection.

Cancellation is allowed only before registry ownership, with owned pause drain/release; after registration it becomes explicit retained recovery/retry. Waiter cancellation never cancels process task. Only latest terminal result retained. requireSettled refuses final/checkpoint if any active/failed transaction, but startup readiness must not count its separate outer activation token as this owner's transaction.

Key callback issue: registry activateAdoption returns after onChange, so process stage cannot be marked active until return. Reentrant owner callbacks must see noncancellable activating stage; they cannot retry/cancel. On return inspect actual registry active state/identity before advancing. Errors after actual activation must retain it as active and never attempt failAdoption on an already active record.

Tests: no factory on busy/capacity/staleclaim/reservedID; publisher drain holds creation; pending callback blocks nested admission/quit; real actor receipt survives refused install and fresh registry attempt; already-installed exact readback prevents duplicate install; endpoint loss/cancelled waiter retains; stale claim after activation holds publication; successful actual claim transfer and actor checkpoint preserve exact content; projection-only retry never re-adopts; unregistered failure releases only exact token; 128live/129reserved proper replacement; source disk-copy operation consumed before handoff (native test later). No fabricated durability receipts, GUI claims or generic ownership rollback.

## Reviewed corrections before implementation

Install provisional active record before every injected application/destination/resource validation callback (only pure scalar validation may precede it). Set noncancellable REGISTERING before calling registry; a nil stored lease during onChange does not mean registration has not happened. Capture session/registry revisions before factory and revalidate provenance, capacity and destination afterward; register against the revalidated exact registry revision, never casually refresh to latest. After active ownership, use typed renewImportClaim(old) with original semantic provenance and resolve it; do not rerun pre-factory admission against an already-live ID. Missing/changed records retain explicit reconciliation failure.

Cancellation API is intentionally narrow: only while draining before registration, set a cancellation request; the owned task finishes actual drain and releases its own hold before refusing. All callback-capable creating/registering/adopting/activation phases refuse synchronous cancellation. Waiter cancellation never owns lifecycle.
