# In-process recovery close leases

Reviewed direction: approach A from the close-lease review. Implementation in progress; native adoption remains planned. Preserve the existing paired checkpoint durability contract: a crash before the next confirmed post-close checkpoint can restore older session placement or an unresolved record. No journal, durable retirement ledger, or lifetime close cap is introduced.

A managed document receives one actor-issued coordinator/document/epoch authority after native capture freezes and legacy work drains. Every later item captures that authority with bytes and revision; a worker cannot fetch/upgrade authority. All legacy mutators reject managed IDs before side effects. Fresh authority is issued only by successful adoption or fresh atomic repair, never by readback. Authorized batches and checkpoints preflight all IDs/tokens/revisions before mutation, preserving exact live-ID coverage and existing resource limits.

Actor API: `adoptManagedDocument(id:) -> RecoveryAdoptionReceipt`, `persistAuthorized(_:)`, `persistAuthorizedBatch(_:)`, `prepareClose(authority:minimumRevision:registryTicketID:) -> RecoveryCloseLease`, `finalizeClose(_:) -> RecoveryCloseReceipt`, `retireClose(_:)`, and `restoreAfterClose(_:attemptID:mutationGeneration:snapshot:) -> RecoveryRepairReceipt`. Prepare is non-destructive and revokes writers. Finalize performs checked deletion; its exact receipt alone can be passed to registry completion. Retire confirms model disposal. Repair keeps the lease on any failure and returns a fresh epoch only after an actual atomic save succeeds. Old epochs fail even at higher numerical revisions. Native installs new authority before reopening admission.

Store checked deletion pins private directory and target descriptors, renames to an owned unique quarantine, checks the moved identity before unlinking it, syncs and rechecks parent/canonical absence. Pre-mutation errors preserve bytes; post-rename errors carry evidence and do not claim deletion succeeded. Unexpected moved objects are preserved, not deleted. A bounded owned-remnant cleanup/absence-validation path is required before repair after uncertainty. Failed removal invalidates capacity and blocks subsequent growth until safe reinventory; no request alone releases quota. Existing legacy remove remains compatible.

Native integration is separate: process-owned close transactions retain the model and lease across cancellation/window closure; a shared pause gate drains checkpoint and legacy work; actual edits/undo/save/composition/baseline updates are blocked. Registry failure requires token-bound fresh snapshot repair. Resume/request the next paired checkpoint only when every active close/repair settles. No user file writes.


## Implemented view-free API and limits

`preflightRepair(authority:snapshot:)` validates the exact open epoch and exact snapshot, performs bounded off-main encoding/directory-byte admission, then non-quarantining recovery inventory for aggregate UTF16/count. It does not write/quarantine recovery/session records or revoke authority. Standard empty private-directory initialization may occur; this is not zero filesystem mutation. Snapshot must stay coherent with the native frozen model. No reservation is made: hold all writers frozen and settle each document completely before preflighting the next. Refusal happens before prepare/revocation; new captured content requires new preflight. Same snapshot is reused unless actual owner content changes.

`minimumRevision` is the highest-issued counter in the **current epoch**, not the durable write count. A larger value is allowed and reserves that fence without acknowledging any bytes. Repair publishes revision1 under a new epoch and returns nextRevision2. If registry rejects a completed repair, keep that returned authority frozen and prepare a fresh lease before retrying; never reuse the old lease. Old deletion receipts are invalidated when a repair begins.

`RecoveryCheckpointItem.authority` and `SessionCheckpointReceipt.recoveryAuthorities` are additive with nil/empty legacy defaults. `commitAuthorizedSessionCheckpoint` uses the same actor and session writer and requires exact captured authorities for all live items. Native/scheduler migration remains separate; legacy checkpoints reject managed IDs rather than acknowledging skipped recovery writes.

Checked deletion uses an owned nonce artifact, not a persistent transaction journal. Inventory refuses retained `.recovery-removal-` artifacts so their bytes cannot silently release quota. On process restart such unresolved artifacts cause explicit resource refusal until a separate safe recovery workflow handles them; no auto-deletion or journal reconciliation is claimed. POSIX name-based operations do not prevent all hostile same-user races; checks preserve observed unexpected objects and refuse mismatched identities, not provide a tamper-proof filesystem transaction.

## Verification

`./scripts/test-recovery-close.sh` freezes actual core plus RecoveryCoordinator into a private Swift5/macOS14 Foundation test package. Current25 tests pass:12 core/store and13 actor tests. Initial actor/store seams produced real runtime failures; a repair-publication absence retry and old-deletion-receipt retirement defect were independently exposed and fixed. Scoped strict formatting and shell syntax checks pass. Native admission, scheduling freeze, user interaction and post-close restart acceptance remain unimplemented/unverified by this test runner.

Independent review added two real counterexamples: an unrelated writer validating repair uncertainty, and successful save followed by parent-check refusal. Publication progress is now transaction-local and survives both; original-parent validation and a fresh successful write are still required before issuing repair authority.
