# Native recovery close integration

Status: proposed native integration of review approach A. No production changes, builds, or runtime claims in this task. The registry close slice and actor/store lease implementation have separate evidence; neither proves native enforcement. Preserve the existing checkpoint crash contract: removal becomes durable session placement only after a confirmed subsequent recovery→session checkpoint. No journal, restart discard ledger, or lifetime close-count limit is proposed.

## Current source findings and exhaustive production recovery-writer map

- `EditorWindowController.recoveryBatch` captures `(id, revision, snapshot?)`, increments `recoveryRevision` with unchecked `+=`, and copies text only for scratch/dirty documents. `captureSessionCheckpoint` reuses that batch; `ApplicationSessionCheckpoints.makeScheduler` pairs those items with session metadata without suspension. This is the production publisher to preserve.
- `scheduleRecovery`/`enqueueRecovery` use the process callback when installed. Without it, a 750ms debounce, periodic timer, and `recoveryWork` task chain still publish captured legacy batches. `prepareToQuit(persistRecovery:true)` and static `persistPreparedRecovery` also publish unqualified batches. These are real standalone compatibility writers, not safe sources of managed authority.
- `discardRecovery` queues legacy `RecoveryCoordinator.close(id:)` after that window's `recoveryWork`, retains only an ID/actor/task in static `pendingCloses`, then later status reports or retries. `closeDocuments` removes the native model immediately, before deletion succeeds. `windowWillClose` repeats cleanup for every local document whenever not preparing quit. Both must stop deleting managed identities; merely installing the checkpoint callback does not disable them.
- `drainPendingCloses` can retry legacy close and removes the pending entry only after success. `finishPendingCloses` is a modal compatibility wrapper. Neither retains a model suitable for repair. New managed transactions must not be inserted in this legacy table.
- `SessionCoordinator.remove` removes unresolved, not live, records through injected `removeRecovery`; default implementation calls legacy actor close. It retains unresolved metadata on failure. Its removal queue is drained by checkpoint preparation and legacy `persist(windows:)`. The latter independently writes Session.json through `saveSession`; no current AppDelegate caller uses it, but it must remain explicitly standalone-only once the process publisher owns publication.
- `RecoveryCoordinator.persist`, `clear`, and `persistBatch` are legacy actor entry points; direct production call sites are the controller paths above and the actor's own paired commit. `RecoveryStore` construction/save is owned by this actor. Managed IDs must be rejected by every legacy mutation, including mixed batches before any mutation, rather than silently skipped.
- `AppDelegate.applicationShouldTerminate` currently pauses/drains checkpoints, freezes each editor with `prepareToQuit(false)`, then calls `commitFinal`. Every veto calls `resumeAfterVeto`. `AppDelegate.editor.onClose` removes the endpoint and requests a checkpoint. Both must consult the process close owner; an unconditional resume cannot release someone else's close/repair pause.
- `canClose`/`windowShouldClose`, close-current/close-all/close-others/right/tab buttons, and `windowWillClose` funnel through the two controller deletion paths. `reopenClosed` creates a new document UUID from clean history; preserve that fresh-identity behavior. LargeFileWindowController close currently cancels paging/search only and has no recovery writer; do not fabricate editable recovery payloads for streaming documents.

## Minimal ownership and proposed interfaces

Introduce one `@MainActor ApplicationDocumentClosing`, retained by the application, using the existing `ApplicationDocuments` registry, existing `ApplicationSessionCheckpoints`, and the same RecoveryCoordinator. It owns `[TransactionID: Transaction]`; each transaction strongly retains the exact editable model/handle, registry request/ticket, captured writer authority, close lease/receipt, repair attempt, and task until terminal settlement. A waiting window task or endpoint callback is never its owner. No detached process task or window-local replacement writer is needed.

Proposed native entry points:

```swift
func requestClose(documentIDs: [UUID], sourceWindowID: UUID) // requests + explicit discard confirmation
func retryRepair(documentID: UUID)
var hasUnsettledTransactions: Bool { get }
func requireSettledForFinalCheckpoint() throws
func endpointDidClose(windowID: UUID) // detach endpoint only, never delete its former local array
```

A close request is captured before confirmation. After any modal confirmation, first check the independent application quit-admission flag, synchronously acquire a checkpoint pause token, and insert the provisional process-owned transaction before calling `registry.beginClose(request, disposition:)`. beginClose revalidates exact request state and may synchronously notify/reenter. If acquisition rejects an already-latched final, no registry ticket has been created. If beginClose rejects, the provisional owner still drains its unused token asynchronously and releases it exactly once; immediate catch→release would fail pauseNotDrained. The provisional process record survives cancellation of the caller. A legacy quit that has started but not yet latched commitFinal is rejected by the independent application flag, not merely by the scheduler finalTask check. Within each batch, fully settle one document prepare/delete/repair before the next document preflight or revocation; parallel items are forbidden without actual capacity reservations. Initially serialize close batches: one process-owned batch may prepare/delete/repair at a time; an overlapping request refuses with actionable busy status. A batch retains its publication pause until every admitted item settles. This bounds the first native adapter and prevents multiple close preparations from competing for repair capacity. A repeated close sees its existing ticket or refuses; it never creates a second deletion. Cancellation before registry admission does nothing; cancellation of an external waiter after admission does not abandon actor completion. Explicit rollback after authority revocation is a repair operation, not Task cancellation.

Native model adapter additions:

- EditorDocument conforms to WorkspaceDocumentHandle with stable id, kind, ownershipGeneration and centralized advancement. Registry is the strong logical owner; window arrays become projections/attachments, not deletion authority. Clean closed history remains bounded and is owned by the registry.
- `recoveryAuthority: RecoveryWriteAuthority?` plus a checked next-issued revision/capture method. Install adoption/repair receipts only through exact owner-context methods. A capture returns immutable authority+revision+snapshot together; it never fetches a newer authority inside an async writer. Exhaustion throws before text capture; it never wraps/traps or changes epoch locally.
- An exact close-state `mutationGeneration` changes on every relevant model mutation (text, encoding/BOM, bookmark/language/presentation metadata if retained in history, baseline/pending-publication identity, and ownership transition). Do not use text editRevision alone for the complete close snapshot. Existing operationID and pending-publication UUID remain independent fields.
- `readCloseState(handle)` reads the exact model, never active tab. It includes `storage.editedMask.contains(.editedCharacters)` for unfinished character edits plus native pending edit/composition/bookmark state. `operationID`, compatibility saving state and macro/async transform activity must be represented or vetoed coherently; operationID alone does not cover all existing busy paths. Do not infer quiescence from textDidChange alone.
- One native `allows(document, DocumentAdmission)` gate composes registry.allows with existing quit/file/composition/pane-install guards. Wire both UI validation and handlers. Disable edit/select across all attached/pooled panes while closing/repairing, restore previous selectability on success/failure reopening, and maintain explicit document status/Retry Repair. IsEditable alone does not prevent native UndoManager or direct owner setters.

The proposed actor signatures agreed for the actor implementation are:

```
adoptManagedDocument(id:) -> RecoveryAdoptionReceipt(authority, nextRevision)
persistAuthorized(AuthorizedRecoveryItem(authority, revision, snapshot?))
persistAuthorizedBatch(...)
prepareClose(authority:minimumRevision:registryTicketID:) -> RecoveryCloseLease
finalizeClose(lease) -> RecoveryCloseReceipt
retireClose(receipt)
restoreAfterClose(lease:attemptID:mutationGeneration:snapshot:) -> RecoveryRepairReceipt
```

Repair receipt contains matching lease/attempt/mutation/publication ID, newAuthority and nextRevision. Exact coordinator/document/epoch tokens are immutable. `minimumRevision` is the highest-issued native capture fence, including captures that never published, and must be at least the actor latest admitted revision. The actor contract confirms that it is not an equality/durability assertion. A fresh repair publishes revision 1 and returns nextRevision 2.

Agreed additive paired-publisher API: RecoveryCheckpointItem.authority defaults to nil solely for never-managed legacy compatibility; commitAuthorizedSessionCheckpoint uses the same actor/session writer and requires exact captured nonnil tokens for all live items; SessionCheckpointReceipt.recoveryAuthorities defaults to [:]. Complete batch preflight must reject an absent/stale authority for any managed ID before recovery or Session.json mutation. The resulting receipt echoes the exact authority and revision map; the reviewed scheduler acknowledgement now compares both against the captured batch and verifies each authority.documentID equals its item ID. Production managed adoption still waits for actor prerequisites and atomic native migration. A separate actor authorized-batch call followed by the existing session writer is NOT a replacement for the existing non-suspending paired actor commit.

## Pause ownership and deadlock prevention

Add opaque process suspension handles to ApplicationSessionCheckpoints rather than expose more boolean pause/resume callers:

```swift
// Scheduler primitive approved for the next independent implementation slice:
func acquirePause() throws -> CheckpointPauseToken
func drainPause(_ token: CheckpointPauseToken) async throws
func releasePause(_ token: CheckpointPauseToken) throws
// Application owner additionally exposes its synchronous capture/close admission check:
func requireCaptureAdmission() throws
```

Acquire inserts an opaque owner-bound token in an active set synchronously, before any suspension, and refuses while the existing final task is latched. It cancels only a waiting delay and prevents further ordinary captures. drainPause validates before and after awaiting the existing ordinary worker; release accepts only an exact successfully drained token. Multiple leases can await the same worker. A canceled waiter never releases authority. Requests while blocked coalesce generation counters, not snapshots. Release consumes an exact drained token once; a duplicate release is refused, and resumes/requests a checkpoint only when all close/adoption/repair/quit holds are released. Initially quit retains the existing independently latched legacy pauseAndDrain/resumeAfterVeto flow. The new active set and legacy latch compose: legacy resume cannot override a close lease, and releasing the final close lease cannot override legacy pause. A future application-level quit handle may wrap that existing latch; it is not a scheduler close lease admitted by commitFinal. A close repair failure keeps its hold and a persistent actionable warning; successful unrelated closes cannot resume the publisher prematurely. This conservatively pauses all recovery during unresolved repair; other documents may still be saved normally, and the UI must say recovery is paused. Do not silently leave the app appearing protected.

Critical cycle to avoid: close cannot await publisher drain while publisher's prepare hook awaits that same managed close. Keep legacy pending-close drain restricted to never-managed legacy work. Managed checkpoint preparation checks the active close set and fails promptly; it does not call `await closeOwner.drain()`. The synchronous coherent capture checks admission again, including zero-window captures. An already captured commit may finish before the close lease is prepared; close revocation happens only after that shared drain. Already-running unresolved-record removals are independent legacy work and must settle before adoption of a colliding ID.

`commitFinal` remains the existing latched final operation. It rejects any active new pause token before latching, while the independent legacy quit pause is permitted. No managed close/repair/adoption may remain. A close arriving after quit starts is refused. If a final checkpoint was already admitted, a new close cannot begin; this policy must be checked synchronously before creating a registry ticket. No final operation waits for interactive repair while repair waits for final publication.

## Ordered migration and close transaction

1. Add model capture/admission adapters and process owner, still unwired. Keep standalone tests explicitly legacy. Register live model handles once, enforce registry capacity and strong ownership, and keep windows as presentation endpoints.
2. At startup/import/new-document adoption, acquire process publication hold and freeze affected model mutation/capture before first await. Stop per-window legacy timer/debounce; await every prior recoveryWork and legacy pending removal for those identities. Startup restoration must finish before the initial managed capture. Actor adoption returns the authority; install it synchronously on the same still-owned model, then reopen admission. Never adopt an already tombstoned close UUID for reopen; create the fresh UUID already used by history reopening.
3. Migrate paired capture and commit atomically as a feature switch: every registered editable live ID has a captured authority; unresolved entries remain metadata and are not manufactured into live snapshots. No partial production mixture where the actor knows an ID is managed but the current publisher drops its authority. Managed standalone enqueue/prepare helpers either route to the one publisher or explicitly refuse; they never silently succeed after a skipped actor write.
4. Close confirmation → check independent process quit/close admission → synchronously acquire publisher pause → insert provisional process-owned transaction → registry.beginClose → apply native freeze → await shared publisher and relevant legacy drains. The provisional record exists before beginClose can notify/reenter. If beginClose rejects, retain that record until its unused token has drained and been released exactly once; no registry rollback ticket is then needed. Registry admission precedes callback-capable native freezing. Re-read exact registry/model state before actor prepare. Strong transaction owns the model throughout.
5. prepareClose revokes writer authority and issues lease without deletion. After awaiting it, revalidate ticket/model/assignment; if stale, retain and repair rather than finalize deletion. finalizeClose produces checked removal receipt or lease-bearing error; only a trustworthy unchanged pre-revocation failure may map registry `.notRemoved`. Every post-revocation failure maps `.uncertain`/recoveryRequired unless actor explicitly returns an exact restored authority. Legacy close failure is never mapped notRemoved.
6. Feed the exact deletion receipt outcome into registry.completeClose. `.closed`: retire the actor close receipt, remove only that registry identity's native attachment/history disposition, then retire the process transaction. Empty-source endpoint closure is a view teardown and cannot clean up a document assigned elsewhere. If retire acknowledgement throws/has not returned, retain process evidence until reconciled; do not request a fresh writer authority for the closed UUID.
7. If registry retains the model after removal/uncertainty, keep it frozen. Obtain registry.beginRecoveryRepair; synchronously capture an exact RecoverySnapshot of that same model, including encoding/BOM and originalPath, even if clean. This nonnil repair publication proves recovery exists; the subsequent paired checkpoint may clear a clean file's temporary recovery. Assert resource limits before copying. Await restoreAfterClose, then revalidate exact attempt/model context, install the returned new authority and nextRevision, and only then call registry.completeRecoveryRepair(success). Registry onChange may immediately capture, so installation must precede reopening. Any refusal keeps repair state and strong evidence; never re-enable old epoch. Receipt mismatch is failure, not a new baseline.

   **Post-publication acceptance is a separate transition.** A confirmed actor repair immediately invalidates the old lease and issues a fresh epoch. Store the returned receipt/new authority in the process-owned transaction before invoking registry/native callbacks; retain the publication hold. If exact registry acceptance rejects due to a changed model or reentrant callback, never retry the old lease. Complete the registry attempt as failed/recoveryRequired if it is still the current attempt. Using the retained new authority and its highest issued fence (receipt.nextRevision - 1 when no later captures were issued), call prepareClose with the same logical registry ticket correlation to obtain a fresh actor lease. This revokes the unaccepted epoch again without deleting the newly published recovery. Then begin a fresh registry repair attempt and publish the latest exact model under that new lease. If fresh preparation fails, retain the new authority, latest receipt, live model, and pause; do not unfreeze or guess an epoch. A later explicit retry resumes this same state. This is a bounded in-process state machine, not automatic infinite retries. The actor contract supports repeated re-lease cycles are supported.

   The model's captured authority field may receive the new authority before registry acceptance, but registry admission remains frozen. Only completeRecoveryRepair's successful exact acceptance may reopen supported mutation; a reentrant registry notification that starts a new close/repair is observed as a new transaction before the prior owner releases its hold. Do not report a successful open state based solely on an actor receipt. Strong process state explicitly distinguishes awaitingActorRepair, awaitingRegistryAcceptance, and needsFreshLease.
8. Release the exact process hold only after registry+actor state is settled, then request the next paired checkpoint. Do not acknowledge crash-safe exclusion until that checkpoint receipt. No original document file is written by close repair.

A source endpoint's forced teardown cannot cancel the transaction or drop the model. Normal NSWindow close returns false until its close batch settles; after success it closes an empty endpoint with a teardown-only flag. If an endpoint disappears anyway, retain the registry assignment/transaction and expose process-owned repair status; repair/reopen attaches the retained model through the registry, without reviving obsolete source callbacks. Do not use windowWillClose's local documents array to infer ownership. Streaming endpoints can use registry close without editable recovery data, but must still settle handle and paging task ownership.

## Native admission audit checklist for implementation

Gate actual NSTextView shouldChange/canMutate, command-key/menu native undo/redo targets and manager invocation, selected-range changes, composition begin/end, tab/pane focus/selection/drag/pin/reorder, split/collapse/restore, save/reload/encoding/Locate/disk action begin and delayed completion, async transforms/macros/bookmark actions, baseline adoption and pending-publication updates. Existing controller callbacks that weakly capture a document must check registry assignment+ownership generation and admission on their second hop. Mutations that bypass supported native APIs remain detectable by exact close state at completion, not magically prevented: retain model and require fresh repair. Do not perform large String equality or scans to implement the admission gate.

Selection/metadata freezing must not change logical close state after registry ticket capture merely because controls were disabled; keep control-state bookkeeping separate. Capture state includes pending edit batches; a direct storage mutation while frozen invalidates the exact completion/repair snapshot. Freeze operation and event generation must detect begin/end ABA even if operationID returns nil.

## Acceptance tests before app wiring

1. **Captured writer authority:** capture A, prepare close, submit A at arbitrarily higher revision before/after repair → reject without disk/capacity/session write. Missing authority and mixed legacy/managed batch reject before any mutation. Authorized paired receipt matches full live-ID authority/revision map; no skipped entry can yield success.
2. **Actual native close failure:** dirty Unicode/CRLF/encoding/BOM model with two panes and undo; inject checked-delete failures before unlink, after unlink and directory sync. Visible logical document retained/frozen and exact process strong handle survives source teardown and canceled waiter. No old epoch admitted; repair freshly republishes and only then enables edits. Readback is not a repair receipt.
3. **Mutation gates:** actual native insert/undo/redo, marked text, selection/tab/pane controls and file.save while lease held cannot mutate or launch a modal; delayed save/transform/encoding/disk callbacks fail exact ownership. Inject direct storage/baseline changes to exercise recoveryRequired rather than claim native freeze prevents arbitrary model access.
4. **Repair races:** wrong coordinator/lease/ticket/attempt/mutation receipts, reentrant onChange during completion, duplicated callbacks, canceled waiter, and source-window disappearance. New authority installed before first callback observing open admission; stale late callback cannot unfreeze a newer repair. Mutate the real model after actor repair succeeds but before the MainActor continuation returns, and separately reenter through registry onChange: reject stale acceptance, retain returned authority, obtain a fresh lease, and prove a fresh retry succeeds without reusing the old lease. Confirm exact current text, undo history and original file bytes unchanged.
5. **Pause ownership:** two closes finishing in reverse order, one repair failure, quit acquire/veto, and already-running ordinary/final writes. Only final hold release resumes; capture during blocked state refuses synchronously even with zero windows; no publisher↔close drain cycle. Generation requests coalesce while paused.
6. **Migration controls:** standalone legacy debounce/periodic/quit helpers still pass for never-managed fixtures; same entry points reject managed models. Existing session unresolved removal remains retryable and cannot delete a now-live managed ID. Managed model adoption waits old queued write and cleanup; reopened history gets fresh identity.
7. **Product state:** close current/other/right/all/window, clean history cap10, last-tab placeholder, moved document then empty-source close, pin/order/selection preservation on failed close. Registry and native projections agree before post-close capture.
8. **Paired durability:** real fresh-process restore after confirmed post-close checkpoint excludes closed ID and restores all remaining exact acknowledged buffers/layouts. Kill before that receipt may reproduce the documented mixed-generation/old-tab outcome; record it as an explicit existing limitation, not a new durable-discard guarantee.

## Remaining interface decisions before implementation

- Actor owner confirmed minimumRevision issued-fence semantics and fresh-authority re-leasing after rejected registry acceptance. Final typed post-revocation failure and repair resource behavior remain actor adoption prerequisites.
- Authorized paired checkpoint entry point and authority-bearing receipt comparison are required before enabling managed IDs in the app.
- Registry recovery receipt currently accepts a caller-created publication UUID; production adapter must construct it only from a verified actor repair receipt, not a generic success closure. Consider restricting that initializer to the trusted adapter boundary.
- The scheduler slice owns the approved acquirePause/drainPause/releasePause scheduler primitive and tests. Its legacy pause latch must remain independent while native close migration is staged; AppDelegate resumeAfterVeto must never override active leases. Registry ownership is not live merely because this primitive passes.
- Native conformance/admission wiring is not yet present in EditorDocument/EditorWindowController. Implement that boundary before routing UI close through the otherwise view-free registry slice.

## Required authoritative repair-capacity admission

The first native close adapter serializes close batches. Before revoking any writer epoch or deleting recovery, the actor performs authoritative repair-capacity preflight against current disk accounting and the retained document's bounded exact repair snapshot. Native scalar checks are only an early guard, never proof of current recovery-directory quota. The actor must reject insufficient capacity before revocation, leaving the existing writer/model open; no close ticket may be silently stranded. The process drains/releases the pause and settles registry retention on that known unchanged result.

A clean file may normally occupy no recovery quota, so its potential nonnil repair payload must be included rather than assumed free. The actor preflight/reservation must account encoded envelope bytes, snapshot count, aggregate UTF-16 and concurrent admitted writes. The one paused publisher, rejection of legacy managed mutations, serialized native batch, and actor serialization establish the initial integration ordering; the actor must still validate its actual capacity/uncertainty before promising repair admission. Repair publication failures remain explicit recoveryRequired with model/lease retained and ordinary recovery visibly paused. No actor-proven clean-clear alternative or journal is required by this selected design, and native code must not invent such a receipt.
