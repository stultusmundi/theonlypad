# Supervised search execution design

Status: root-reviewed architecture for staged implementation. No supervisor, protocol or native integration is implemented by this document. The preceding engine-error task must be independently approved before semantic files change. Candidate byte/deadline budgets require measurement before production acceptance; the user’s routine-design approval waiver applies.

The root review removed unnecessary public capture payloads, required linear scalar validation, preserved existing native text/identity checks without misusing recovery revisions, and separated bounded read-only shutdown from durable-document quit authority. The first executable stage is [single-enumeration semantics](../plans/2026-09-10-search-single-enumeration.md). Subsequent stages below remain required and receive their own reviewed executable plans before implementation.

```mermaid
flowchart LR
  Panels[Document and folder panels] --> Admission[Shared admission and byte reservations]
  Admission --> Codec[Bounded snapshot and codec work]
  Codec --> Supervisor[Process supervisor]
  Supervisor --> Helper[Sequential Foundation helper]
  Helper --> Validation[Complete response validation]
  Validation --> Delivery[Current document and generation checks]
  Supervisor --> Reap[Terminate and reap before reuse]
```

## Recommendation and alternatives

Choose **one application-owned supervisor with one sequential bundled Foundation helper process**, shared by document, folder, and subsequent open-document search. Keep the helper healthy across ordinary requests to avoid launching tens of thousands of processes in a folder search. Kill and reap it on cancellation, deadline, protocol violation, or untrusted termination; do not replace it before reap. Keep all queueing in the parent, never a second queue in the helper.

| Approach | Merits | Limitation and decision |
| --- | --- | --- |
| In-process Foundation callbacks, optionally direct ICU time/stack limits | Small integration; current Foundation preserves dialect. Direct ICU offers explicit matching limits. | Cannot independently stop a blocked compile, bridge, replacement allocation, or callback-starved match. Direct ICU adds engine/linkage/semantic migration. Retain cooperative checks as a secondary mechanism, not the C-08 containment solution. |
| Bundled XPC service | Structured IPC, launchd-managed lifecycle, possible later entitlement separation. | Connection invalidation alone is not proof that a specific active engine invocation has stopped. Hard task termination and exact single-process accounting would still need an explicit service lifecycle design; launchd, XPC bundle configuration and serialization introduce more integration than this SwiftPM app needs. Credible if a security-sandbox product requirement is separately adopted. |
| Owned executable plus bounded pipe protocol | Explicit child identity, signal/reap lifecycle and transport budgets; no engine change; fits SwiftPM/package tooling. | Parent must implement framing, lifecycle and malformed-message handling. Process isolation is not a security sandbox and does not establish an RSS ceiling. **Selected.** |

Apple describes XPC services as launchd-managed; this is a different lifecycle from a directly waited child. [Apple XPC service guide](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingXPCServices.html). ICU exposes matching time and stack limits, but adopting them would not establish Foundation's configuration or a compilation deadline. [ICU regex API](https://unicode-org.github.io/icu-docs/apidoc/dev/icu4c/uregex_8h.html).

## Current integration facts

- `SearchService.matches` and `replacing` compile and enumerate synchronously. The document panel invokes both for Replace All, giving two enumerations and budgets. Selection bounds use transparent bounds and no anchoring bounds, Unicode word boundaries, and UTF-16 scalar validation. Regex replacement uses the existing numeric capture parser, including `$0`, optional unmatched groups and backslash quoting. Preserve these semantics.
- `SearchPanelController.start` captures a String before creating an unbounded detached task. Cancel invalidates UI generation but releases its task reference immediately. `EditorWindowController.showSearch` binds one original model/pane and currently uses exact text comparison at selection/replacement. Snapshot and application admission must remain native-owned.
- `FolderSearch.search` performs discovery and checked reads, then synchronously searches each UTF-8 nonbinary file. It stores source text for hits, with 50,000-entry/10 MB-file/10,000-hit/100 MB source-byte caps. `FolderSearchController.stop` allows another worker immediately. A supervisor must not leave this unbounded discovery/read-worker path behind.
- Package.swift currently has PadCore, TheOnlyPad and core tests only. `scripts/package.sh` copies and signs one executable. `scripts/sbom.py` inventories its hash, and `check-package.py` compares bundle/archive bytes. A helper must be explicitly built, copied, signed, inventoried and checked; a developer executable beside the app is insufficient.
- Selection/open-document scopes, complete folder replacement/backup flows, and 1 GB regex support are not implemented by this change. Existing large-file search is literal byte search; keep its capability label distinct. Full C-07/C-08/I scope remains required across staged work.

Sources inspected: the two reviewed regex documents, SearchService.swift, FolderSearch.swift, SearchPanelController.swift, FolderSearchController.swift, the `showSearch` adapter in EditorWindowController.swift, Package.swift, package.sh, sbom.py and check-package.py. The active error worker may change flag handling/messages after this read; implementation must integrate its final reviewed source rather than snapshot these older versions over it.

## Ownership, admission and exact interfaces

Keep types view-free in a proposed `SearchExecution` module depending on PadCore. The helper executable depends on the same semantic implementation; native orchestration belongs in `ApplicationSearches`, supplied to panels by the existing application owner. No per-panel supervisor or direct search fallback if the helper is missing.

Proposed public-to-module interfaces (names to freeze in the executable plan):

```swift
struct SearchJobID: Hashable, Sendable { let rawValue: UUID }
struct SearchConsumerID: Hashable, Sendable { let rawValue: UUID }
struct SearchReservationID: Hashable, Sendable { let rawValue: UUID }
// SearchExecutionOperation comes from PadCore: .find or .replace(template: String).
struct SearchInput: Sendable {
  let text: String
  let utf16Length: Int
  let scope: NSRange? // full original coordinates; nil means whole text
}
struct SearchExecutionRequest: Sendable {
  let id: SearchJobID
  let query: SearchQuery
  let input: SearchInput
  let operation: SearchExecutionOperation
  let limits: SearchExecutionLimits
}
struct SearchExecutionResult: Sendable {
  let id: SearchJobID
  let output: SearchExecutionOutput // shared PadCore ranges and optional replacement
}
protocol SearchExecuting: Sendable {
  func execute(_ request: SearchExecutionRequest,
               reservation: SearchReservationID) async throws -> SearchExecutionResult
  func cancel(_ id: SearchJobID) async
  func shutdown() async -> SearchShutdownResult
}
```

No public forgeable reservation grants capacity: the supervisor stores and checks its own issued IDs, consumer, reserved sizes, operation ID and consumption state. `execute` is usable only with the corresponding admitted reservation. Typed errors distinguish existing SearchError values from `queueFull`, `consumerBusy`, `helperUnavailable`, `protocolMismatch`, `malformedResponse`, `helperExited`, `executionDeadline`, `preparationDeadline`, `resultBudget`, `shutdown`, and `stopUnconfirmed`. Do not merge engine failure into unreadable-file or successful partial reports.

Native coordinator entry is synchronous `submit(consumer:descriptor:capture:completion:) throws -> SearchJobID`. Descriptor contains bounded query/options, operation, scalar input-size estimate, and source identity/context; capture is a weak-source MainActor closure returning an immutable SearchInput plus an opaque native delivery context. No closure captures a prebuilt large String while queued. ApplicationSearches issues reservation only when active input/result budgets permit capture, then invokes capture and verifies exact source context again. Reentrant capture can neither replace the current reservation nor launch twice. Actual String UTF-16 length is checked off-main against the reserved scalar bound before transfer; increased text is refused, not undercharged.

At most **eight logical jobs**, including active jobs and batches, process-wide; at most one outstanding job per consumer. Reject restart with an actionable “Stopping previous search” until that consumer's preparation/child resources quiesce. Cancelled waiters do not release capacity; owner cancellation does. Metadata-only queued jobs can be cancelled immediately. Queue full refuses before document capture. No unbounded latest-request chain or queued snapshot closures.

One bounded off-main encoding/decoding lane and one child request can run; the watchdog/control queue must never execute large encoding, Foundation matching, or a blocking read/write. Large native snapshot capture itself still requires an immutable copy/bridge on the owning thread; do not read NSTextStorage on a worker. Reserve before capture, avoid another UI-thread encoding/count scan, and measure capture cost at 100 MB. This proposal does not prove an arbitrary NSTextStorage snapshot is constant-time or meets the UI latency target.

## Process and cancellation state machine

Child states: `absent -> launching -> handshaking -> ready -> executing(id) -> ready`, or any active state to `stopping -> reaping -> absent`. Launch, stop and reap receipts are bound to a monotonically distinct child generation and exact PID; late events for an old generation do nothing. A serial control queue handles state transitions and deadline events. Descriptor I/O is nonblocking and event-driven, with bounded work per event; worker encoding/decoding completion posts back to control. There must be no task-group scope that waits for uncooperative computation before returning timeout.

Use an absolute executable path and posix_spawn, never a shell or PATH lookup. Set close-on-exec descriptor discipline and pass only request/response/control pipes; reset inherited signal masks/dispositions deliberately. The helper does not launch descendants. A single lifecycle owner performs `waitpid` and signaling; no competing Process terminationHandler/reaper. Serialize signal/reap so an already reaped PID cannot be signaled after reuse. Test spawn errors and EOF-before-handshake. [Apple spawn contract](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/posix_spawn.2.html), [Apple waitpid contract](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/waitpid.2.html).

Start the parent operation deadline **before launch/upload**, not after an engine-entered message. Cancellation or expiry marks one terminal failure, closes upload, stops accepting response data and immediately sends SIGKILL to the still-owned child. Cooperative progress checks remain for useful typed early exits; no graceful waiting period is required before forced stop. Drain/close descriptors and confirm exit/reap before freeing the physical process slot or launching another helper. A typed failure can reach UI before reap, but UI must not label it “worker stopped” until confirmed. Reap grace expiry reports `stopUnconfirmed`, quarantines the physical slot and keeps background bounded reap observation; explicit retry may inspect that same child, never create a replacement alongside it.

Normal success requires a completely validated terminal frame stating the helper has released request state and returned to its sequential request loop. One response ID and one terminal event only. Protocol data received after terminal or an out-of-order ready frame is fatal. The parent publishes only after off-main validation finishes and the reservation is still current. A completion/deadline race is decided once on control; no partial output or a late zero exit can turn timeout into success. Cooperative engine errors can retain a healthy child after an exact terminal frame; crashes, malformed protocol and stopped children cannot.

The helper has an independent parent-control-pipe EOF watcher that calls `_exit` if the parent disappears, including while its engine thread is busy. Do not rely on the engine reading its next request. This is operational cleanup for the trusted helper, not protection from a malicious helper. Parent death/launch failure/idle timeout are required subprocess tests. Use a bounded idle lifetime (10 seconds) to drop retained engine heap; folder work reuses the same process across files while active.

A launch syscall or parent filesystem operation itself may stall: keep launch/read lanes reserved, return a typed unavailable/unconfirmed outcome, and do not pile up replacement work. The hard-stop claim applies to a known owned child, not a universal hard bound on arbitrary kernel calls or parent execution.

## Deadlines, fairness and byte accounting

Initial configurable policy proposed for tests: cooperative engine budget 1 second; parent operation envelope `2 seconds + (input wire bytes + reserved output wire bytes) / 20,000,000`, capped at 25 seconds for supported limits; explicit cancellation has no such delay. The size allowance includes startup, transport, compilation, matching, replacement and response. This is a conservative proposed policy, **not measured throughput**. A timer reaction target of 50 ms and reaped-child target of 250 ms are reference-host acceptance targets under stated load, not real-time guarantees. Large-pattern compilation may consume the whole parent allowance even if cooperative matching budget is 1 second. Publish the distinction rather than calling it a universal one-second timeout. The separate bounded feasibility probe informs lifecycle tests, not throughput defaults.

These numbers are experimental defaults only: measure cold startup/handshake and full 100 MB transport (including worst supported 200 MB UTF-16 wire payload) before accepting a production default. Record phase timestamps independently: admission, capture begin/end, launch return, handshake, upload complete, engine entered, terminal decoded, stop requested and reaped. Parent deadlines begin before launch even though the engine-entered marker may arrive later. Queue wait and native capture costs must not disappear from responsiveness measurements.

Queue wait is separate and cancellable; show queued/running/stopping status honestly. Batch execution yields between files/documents so a large folder cannot monopolize the helper. Use FIFO round-robin across admitted consumers, one file per turn; never preempt a successful active file by launching a second process. Batch validation on empty input also goes through the helper. Initial logical batch active-time ceiling: 120 seconds, with explicit typed incomplete/timeout outcome, no complete report; queue waiting excluded and separately reported. This policy must be user-visible and may be tuned using measured normal-folder runs; not silently reset per file.

Preserve existing semantic ceilings: native 100,000,000 UTF-16 input/output, pattern/template 4,096 units, at most 100,000 matches and 1,000,000 aggregate retained ranges including captures. Folder retains its tighter caps. A 100 MB UTF-8 ASCII document is within the native ceiling; arbitrary byte encoding is decoded by the existing document owner before search.

Use UTF-16LE text on the wire: input/output maximum 200,000,000 bytes each; match-only wire range records at most 1,600,000 bytes (100,000 pairs of UInt64). Captures remain internal to the helper's one-enumeration replacement and its existing 1,000,000-range semantic limit; no current consumer needs public capture payloads. Explicit candidate global ledgers: one active request with at most 640,000,000 bytes of charged input/output/codec staging; at most 768,000,000 bytes of retained result/source-evidence payloads across consumers. Reserve worst-case result bytes before capture so completion does not unexpectedly displace another panel's results. The retained budget includes both original expected text and replacement while confirmation is pending; a 512,000,000-byte ceiling would not hold the maximum 600,000,000-byte UTF-8 pair and is therefore rejected. Transfer the exact payload credit from active to retained ownership without an untracked duplicate; reservations may be conservative, but each actual buffer has one recorded owner. Reject excess work explicitly; release a consumer's previous results when starting its next search. These proposed budgets require cold-start/full-100-MB measurement and a concrete allocation ledger before adoption; they are not an RSS estimate or permission to reduce supported input silently.

Budget accounting must distinguish wire UTF-16 from Swift UTF-8 payload: a BMP scalar can occupy three UTF-8 bytes per UTF-16 unit. A maximum input/output pair can therefore retain 600,000,000 bytes of UTF-8 text alone. The candidate 640,000,000-byte active budget requires streaming codec chunks rather than additional full-sized wire Data buffers, and explicit charges for the boundary index and ranges. Measure and review actual staging before accepting the policy; neither presumed COW sharing nor UTF-16 wire size proves allocation cost.

All owned Data/String serialization copies and long-lived result evidence must have a ledger owner and release point; no Foundation `readDataToEndOfFile` or unbounded stderr accumulation. Use bounded 64 KiB transport chunks, at most 1 MiB in-flight buffering per direction. Actual Swift/NSString COW backing, ICU heap, allocator fragmentation and existing document/undo storage exceed these payload counts. Do not claim RSS bound from a byte ledger, setrlimit, or sampled memory. Apple's documented RLIMIT_RSS is memory-pressure preference behavior, not a dependable hard ceiling. [Apple resource limits](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/setrlimit.2.html). Use no-core-dump policy and optionally a tested child CPU limit as additional containment; neither replaces parent deadlines. A hard RSS guarantee requires a separately validated platform mechanism and remains outstanding if requested by acceptance.

To limit healthy persistent accumulation, recycle after 32 completed requests or 512,000,000 cumulative input/output wire bytes, whichever occurs first, plus the 10-second idle policy. Recycling means explicit exit/stop and confirmed reap before replacement; it does not make a per-request RSS guarantee. Optional working-set sampling can trigger earlier recycling/termination, but sampling cannot prevent a peak between samples. Test many benign requests and repeated high-capture patterns to expose retained heap separately from parent snapshot accounting. A cancelled encoder/decoder retains its lane and byte credits until it actually finishes, even if its caller has already received cancellation.

## Protocol and semantic fidelity

Binary protocol v1, explicit little-endian fixed-width integers; 32-byte fixed header: magic UInt32, version UInt16, message kind UInt16, payload byte length UInt64, request UUID 16 bytes. Handshake binds protocol/build identifier and child generation before any input. Request metadata has fixed numeric mode/options/operation tags, optional scope, limits, and explicit pattern/template/text lengths. Unknown tags, unsupported version, nonzero reserved bits, duplicate/out-of-order frames and length overflow fail closed. Pattern/template blobs bounded to 16 KiB each and independently checked in UTF-16; no general object unarchiving or arbitrary JSON graph. The input can be chunked in transport but is one complete original text for matching.

Validate all arithmetic using subtraction/division bounds before conversion to Int or allocation. Enforce cumulative payload/frame/chunk limits, exact expected count and EOF handling. UTF-16 must be well-formed; reject unpaired surrogates rather than replacing them. Response match ranges must be in bounds, scalar-safe, ordered and nonoverlapping where the operation requires it. Validate operation/result shape, count and replacement length off-main. Unmatched captures remain helper-internal and never cross the wire. Never trust an incoming size merely because it is below UInt64.max.

Scalar validation must take **one linear UTF-16 input pass plus O(1) boundary lookup per range endpoint**. During off-main input encoding, build a packed boundary bitset indexed by UTF-16 offset, including EOF: mark an offset invalid exactly between a valid surrogate pair; reject malformed pairs during the same pass. Size is `ceil((utf16Length + 1) / 8)`, at most 12,500,001 bytes at the native ceiling. Each received match checks start/end by indexed bit lookup after subtraction-safe bounds validation; never restart a Swift UTF16View traversal for each of 100,000 matches. Keep the bitset tied to the exact immutable input/reservation through response validation, then release it. Charge it to active codec staging, alongside the input encoding and bounded range array. Output replacement UTF-16 validity/length is checked in its single streaming decode pass; no output boundary table is needed because response ranges describe the original input. Code-unit buffering must remain incremental so the bitset does not imply an additional 200 MB UInt16 array. Differential tests must verify this algorithm and instrument pass/lookup counts, not infer complexity from wall time alone.

No partial response may become successful results. Whole-word wrapping, case behavior, literal metacharacter escaping, escaped-text NUL/newline semantics, inline regex flags, anchors, lookaround, backreferences and zero-length advancement stay in the **same SearchService implementation**. Do not chunk by line, concatenate open documents, rewrite patterns, or switch engines. Selection searches send full text plus range, retaining transparent/no-anchoring bounds; the selection edge must not become a synthetic word/document boundary.

After the narrow error worker lands, add an additive `SearchService.execute(_:in:scope:operation:) -> SearchExecutionOutput` semantic primitive that compiles/enumerates once and builds count/ranges/replacement from the same accepted results. Existing `matches`/`replacing` remain source-compatible wrappers. Preserve current template parsing/error precedence and first terminal engine/cancel/limit failure. Replacement within a selected scope leaves prefix/suffix intact. Native Replace All uses the single result and revalidates original source context after confirmation before applying its one existing undo group. The helper never writes original files, recovery, or session data.

Trust boundary: pattern/input can exhaust or crash Foundation; child output may be corrupt and must not mutate application state without validation. This contains execution and transport errors. It is **not an OS security sandbox**: the ordinary child runs with the user's credentials and can technically access user resources. Passing no paths, no network API, a minimal environment and no unrelated descriptors reduces accidental exposure but does not deny filesystem/network syscalls. No arbitrary helper override in production, no shell, no document text in argv, diagnostics, temp files or logs. Platform crash-report handling is a separate privacy concern; disabling core files is not a promise that no OS diagnostics exist.

## Native, folder and open-document stages

Document delivery context must retain exact model/document ID, ownership generation, originating endpoint/pane, scope and panel generation, plus the immutable expected text used by the existing adapter. On delivery and after any confirmation, check current owner/assignment, pending `.editedCharacters`, composition/save/quit state and existing selection/edit admission. Preserve the existing exact UTF-16 text equality guards for both navigation and replacement. The model's recovery revision is not a general edit-version authority and must not be reused as one. Introducing a general edit revision or replacing text equality requires its own separately designed/tested mutation coverage; this supervisor proposal neither assumes nor requires it. Never convert a helper response into fresh authority. No helper waiting is allowed inside the main-actor admission callback. Closing a panel cancels its job/result lease without blocking the UI; shutdown is app-owned.

Folder traversal remains a separate bounded lane: at most one active discovery/read worker process-wide, including a cancelled worker that has not returned. At most one file's search input outstanding. Convert the folder orchestration to async iteration and await the shared executor per file; preserve checked file identity, globs, skips and source-evidence caps. Progress is one coalesced latest value per batch, not one queued MainActor task per event. Retain report/source evidence under global result credits (one snapshot per file, hits reference its ID); the old hits-with-text adapter must not duplicate buffers unnoticed. Any regex failure makes the complete-report operation fail even if prior files had hits. Cooperative filesystem cancellation remains explicit; hard discovery/read cancellation would require a separately scoped file-reader helper, not a false claim from this regex helper.

Open-document orchestration is a required later stage: enumerate each logical registry document once, preserve dirty snapshots and per-document contexts, capture lazily under reservation, search separately, and aggregate only after all requested documents complete. Do not search each pane or substitute disk content. Retained results must identify document IDs and contexts, not only paths. Multi-file replacement preview/backup/publication is another required stage using existing authoritative file-write contracts; helper output alone grants no write authority. 1 GB literal mode remains separate; no claim of 1 GB ICU execution within 100M limits.

On application quit, close search admission, invalidate native delivery generations, cancel metadata-only jobs, request cancellation of active parent lanes, and immediately stop the exact owned child. `shutdown()` has a bounded wait and returns either `.stopped` (child reaped and every parent lane quiescent) or `.pendingCleanup(child: SearchChildStopState, parentLanes: Int)`, preserving actual process/lane identities and reservations in the owner. `SearchChildStopState` distinguishes `.none`, `.reaped` and `.stopUnconfirmed`; a pending launch is also retained and cannot start another child. Pending codecs/read workers have no valid UI or file-publication capability after invalidation. Late launch completion must stop/reap its resulting child under the original shutdown generation.

**Search shutdown is advisory to app exit, not a new indefinite Quit veto.** Read-only search or a stuck parent filesystem/codec lane must not block termination indefinitely. The existing durable-document/session/recovery quit protocol remains authoritative: call the bounded search shutdown alongside it, record an unconfirmed state honestly, and allow normal process exit if the durable owner authorizes quit. Do not label “exit permitted” as a stopped/reaped receipt. OS process exit ends parent threads; the helper's independent control-pipe EOF watcher exits when parent pipe ownership disappears even if its engine thread is busy. Exact parent-issued termination and that EOF path need their own tests; neither is a claim that a malicious or arbitrarily unschedulable helper always exits within a real-time bound.

If durable quit is vetoed, retain the search owner and its stopped/quarantined state. Reopen search admission only for actually available slots; keep a stuck codec/read/child slot reserved and display its failure, rather than reviving old deliveries or accumulating replacement workers. An explicit search retry can inspect retained cleanup state; it cannot manufacture quiescence. No new modal “search must stop before you can quit” requirement is introduced.

## Packaging and resolution

Add `PadSearchWorker` executable product/target and a small shared protocol/supervisor module, retaining Swift 5 language mode/macOS 14. Build both executable products explicitly. Bundle helper at `Contents/Helpers/PadSearchWorker`; strip distributable debug paths, sign nested helper first then enclosing app, verify strict signatures and architecture/minimum OS of both. Update SBOM with helper component/path/hash and check-package required inventory/version/digest checks in addition to existing byte-for-byte archive checks. No `codesign --deep` as a substitute for intentional nested signing. Local ad-hoc verification is distinct from Developer ID/notarization/release.

Production resolution uses the app bundle's fixed relative helper URL and rejects missing/nonregular/nonexecutable or unsupported protocol artifacts; never falls back to in-process regex, PATH, working directory or a downloaded helper. A developer launch may use a separately injected resolver for an explicitly built sibling SwiftPM product; package builds do not honor that override. Tests inject only an absolute path to their own synthetic helpers. Test relocated/offline bundles and archive extraction. Code-signing/identity checks must use actual release packaging policy, not claim a hardcoded ad-hoc identity authenticates hostile same-user replacement.

## Bounded implementation stages and evidence

1. **Semantic primitive and protocol:** wait for independently approved engineFailure change; additive one-enumeration result API; benign differential fixtures for all modes, captures, scoped transparency, NUL, Unicode, EOF/zero-length and replacement errors. Count actual enumeration calls. Incremental decoder tests for integer overflow, malformed UTF-16, unknown tags, truncated/oversized/duplicate frames. No adversarial patterns in the runner.
2. **Supervisor process core:** injected clock/launcher/transport/reaper state tests, then real synthetic helper executables: no-read upload, partial/flooded response, no-ready completion, early exit, ignored graceful signals, infinite loop and parent EOF. Every real child test has an independent outer watchdog. Assert one terminal event, one reap, no PID reuse signal, no new child while stop unconfirmed, bounded queue/staging, cancellation at launch/upload/parse/ready races. Test healthy sequential reuse and idle exit.
3. **Actual helper and package seam:** genuine Foundation parity, with all pathological cases only in child under supervisor AND independent test watchdog. Engine-entered handshake distinguishes engine execution from launch stall. Preserve exact source/protocol provenance, process exit/reap observations, and benign next-launch success. Packaged helper resolution/signing/archive tests must pass before enabling production routing.
4. **One native document path:** actual owner admission/snapshot/selection/replacement adapters, all modes, one enumeration for Replace All, two panels and rapid cancel/restart, stale edits/composition/transfer/close/quit, no late mutation, no in-process fallback. Hidden tests do not establish interactive latency.
5. **Folder shared admission:** async per-file worker use, single bounded read lane, fairness/progress coalescing and failure-after-earlier-hit. Discovery/read stalls are separate fixtures and limits. Repeat a cancelled stalled folder then new request: prove no accumulated readers or helper children.
6. **Required scope completion and measurements:** selection/open-document UX, multi-file preview/backups, repeated 1/10/100 MB normal and pathological-line runs, memory high-water observations, cold/warm launch, responsiveness and physical cancel/focus under allowed GUI access. Retain existing 1 GB literal-viewing distinction. Tune policy with evidence; do not lower supported input silently or mark all C/I complete from helper tests.

Acceptance separates: (a) cooperative ICU callback timeout, (b) parent timeout decision/signal latency, (c) observed child exit and exact reap, (d) no replacement until reap, (e) bounded explicitly charged bytes/worker counts, and (f) measured RSS—not a guarantee. None implies the others. If an outer watchdog fires, the test fails and cleans only its owned group; post-return elapsed assertions alone are insufficient.
