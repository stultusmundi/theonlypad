# Native external-file monitoring integration map

Status: read-only source/design review; no native monitor integration, implementation, builds or GUI performed. References are current symbol/line anchors and may shift after edits. Core ExternalFileProbe/ObservedFileState exist; no production FileMonitorService, DocumentFileStateController, baselineRevision or file-action context is present in Sources/TheOnlyPad at this review.

## Ownership and missing interfaces

- One process-owned injected FileMonitorService, ideally retained by AppDelegate and supplied to every EditorWindowController including restored/repair windows. Do not create one worker pool per window/pane.
- One DocumentFileStateController per EditorDocument: registration/cancellation handle, current live context, baseline revision, reducer state, pending reconciliation, and weak UI notifier. It must not own panes/window strongly. EditorDocument currently has editRevision but no monitor baseline revision (`Sources/TheOnlyPad/EditorDocument.swift`). Do not reuse editRevision: typing, undo and attribute/encoding transitions have different save authority.
- Required coordinator boundary: establish file adoption from `(documentID, URL, originalBytes, savedEncoding, savedHasBOM)`; defer delivery while logical operation/composition active; rebind acknowledged baseline; invalidate/cancel; force/manual check; access LIVE latest-issued observation context without filesystem work or blocking on workers.
- Latest-issued token bridge is critical: `ObservedFileState.accept` requires incoming token equal to the live owner context, including sequence. Setting currentToken from the arriving callback defeats pending-newer-request rejection. Service/native interface must expose or synchronously validate its current registration/request context before MainActor adoption, including the second hop after service delivery. Manual one-shot requests need request UUID + captured/live document URL/baseline/lifetime guards even when registration is unavailable. Never pretend the 129th tab has a registration.
- Add DocumentFileActionContext capturing logical document ID, accepted full token, original URL, editRevision, baselineRevision, current encoding/BOM, pending-publication identity and pane selections keyed by UUID. Prefer a document-scoped operation UUID/busy token to prevent stale completion from unfreezing a newer transaction.
- Existing `onOpenedURL(URL)` lacks document identity and fires for successful selection of an already-open buffer. It is an MRU notification, not a safe monitor-registration event (`EditorWindowController.open`, lines471–600; AppDelegate.newWindow lines64–70).

Encoding conversion and native undo of conversion change current metadata only, never monitoring saved-byte authority. Revision overflow requires a fresh context, not wrapping acceptance order.

## Save and uncertainty ordering

`save(document:saveAs:)` starts at line893. Destination chooser may run a nested modal loop; existing post-dialog guard verifies membership/window/quit/saving before snapshot. Set monitor delivery deferred with the admitted save transaction when `document.saving = true` (line922), before detached encoding/backup/validation/write. No ignored-own-write time window.

Detached save retains exact existing behavior: retry validates PendingDocumentPublication evidence and exact attempted bytes; ordinary Save compares originalBytes; Save As is create-only; backup precedes changed-byte publication. Monitor must not substitute observed disk bytes into expected bytes.

Success clears saving, checks live membership, assigns acknowledged URL/baseline and clears pendingPublication before interactivity/refresh/language/recovery (lines952–969). Insert rebind and baseline-revision update after those assignments and before presenting reconciled monitor state. Failed operation restores monitor presentation against the unchanged baseline and queues a fresh check; no revision increment for failed publication.

Uncertainty branch lines970–991 preserves exact evidence/bytes, potentially for a different Save As destination; keep watch authority on original URL. If original URL is nil, remain an unwatched scratch despite an attempted destination. A matching observation never clears uncertainty, marks clean, suppresses recovery or authorizes redirecting retry evidence. Save completion must still acknowledge a successful actual write; do not casually add a quit guard that discards a durable-save receipt while global quit is waiting to freeze windows.

`document.saving` is also used for reload/encoding/formatting/macro work. Observation acceptance must treat the actual document busy state conservatively, not assume this flag always means original-file I/O. `refreshInteractivity(document)` (lines99–103) is the existing lifecycle-aware restoration helper; it must not perform filesystem work or inadvertently flush observations before baseline updates finish.

## Existing reload/encoding guards versus external reload requirements

- `execute` lines628–635 and `isCommandAvailable` lines859–883 reject current composition and closed/quit state. Direct callbacks can bypass those entry points, so they are not sufficient transaction admission.
- Existing private `reload` lines998–1080 starts from `current`, rejects window/quit/shouldAccept and window-wide `isRecordingMacro`, then captures document/URL. It confirms discard BEFORE read, sets saving, and rechecks membership/window/quit/shouldAccept on completion. It does NOT independently recheck recording/composition after modal/async work, retain edit/baseline/observation revisions, or preserve/clamp every pane selection. New external callbacks must not reuse it as if these stronger guards already exist.
- `isRecordingMacro` is window-wide (`recordingDocumentID != nil`, line252). Preserve that existing conservative veto at invocation and after every await/modal return; don't accidentally weaken it to a currently focused unrelated pane. Replay uses document busy state; macro library saving is a separate global flag.
- Existing `confirmDiscard` lines1911–1923 has Cancel as first/default choice but only generic unsaved-change wording. External dirty/uncertain reload needs explicit pending-publication warning and revalidated context after the dialog.
- Existing `Self.read` lines605–617 uses resource values/FileHandle and DocumentCodec; it has100MB read cap but lacks ExternalFileProbe's no-follow/parent/observation admission. Do not route external reload/disk copy through it or silently change ordinary legacy-open symlink behavior.
- External decoder must reject longest unsupported UTF32 BOMs first; supported UTF8/UTF16 BOMs win via decode without explicit encoding. Only BOM-less external bytes use savedEncoding, not current conversion preference. Existing explicit Reopen with Encoding must continue honoring explicit choice.
- `showEncoding` lines1081–1131 captures document, but Reopen displays that document then invokes current-based reload. Its conversion path calls `convertEncoding`/`setEncoding` lines1133–1182: these change current encoding/BOM with undo and recovery, not originalBytes/savedEncoding. Monitor baseline revision must not advance on conversion or conversion undo.

Proposed external reload sequence: capture full document/action context; validate reducer action with live dirty/pending/busy/composition/recording/quit/lifetime; freeze all pooled panes via logical busy token; read/decode/revalidate using probe off-main; recheck context; if dirty/uncertain, ask explicit discard with Cancel default; recheck context plus disk observation after modal return; atomically adopt decoded storage and exact bytes only on success. Preserve pane identities/axis and current focus; clamp saved selection for each still-applicable pane via RestoredViewState off-main. Clear native undo, bookmarks and all pending composition/bookmark bookkeeping consistently, trigger one document language/recovery/checkpoint update and rebind once. Every failure keeps existing bytes/baseline/undo/pending evidence and restores only lifecycle-eligible panes. Switching to another tab during read must never redirect replacement or steal that tab's focus.

Open Disk Version uses the same validated external read/decode but creates a NEW URL-less scratch with preserved decoded encoding/BOM. No empty placeholder on failure, no source baseline mutation, no original-file Save authority. Locate performs explicit stable regular-file selection and exact originalBytes comparison; only then may URL-only adoption update MRU/session once. Different bytes require scratch copy or explicit reload, never merely a new expected-save baseline. Pending publication prohibits URL redirection.

## Close, quit, activation and session map

- `closeDocuments` lines1781–1803: cancellation belongs after accepted close decision and immediately before actual removal/recovery discard. Cancel all registrations for closing documents explicitly. Clean closed documents are retained in `closedDocuments` (up to10), so deinit-only cancellation leaks active watches and deliveries. Do not stop monitoring on a canceled close attempt. New delayed monitor dialogs must revalidate full context after nested modal loops; don't widen existing close path's reliance on pre-confirmation guards.
- `windowWillClose` lines1892–1908: set windowClosed first (already done), invalidate all live document delivery and close monitor action panel, cancel registrations regardless of whether recovery is retained for quitting. Descriptor cleanup stays asynchronous in bounded service workers; window close does not wait for monitor I/O.
- `AppDelegate.applicationShouldTerminate` lines290–325: suspend global monitor delivery immediately with `preparingQuit = true`, BEFORE awaiting startupTask/checkpoint drain. New registrations created by finishing startup while suspended must inherit suppression. The per-window freeze happens only later; waiting until then leaves an avoidable global-quit delivery gap.
- Veto paths lines299–306 and310–318: cancelPreparedQuit on every window, clear global preparingQuit, then resume+force reconciliation along with existing recent/checkpoint resume. Never wait for a blocked monitoring syscall to veto or terminate. Successful final checkpoint and external-process cleanup ordering stays unchanged.
- `EditorWindowController.prepareToQuit` lines2380–2412 refuses recording/composition/file operations, disables panes and drains existing recovery. No monitor drain belongs here. `cancelPreparedQuit` lines2414–2425 restores interactivity with mayMutate semantics.
- Periodic paired capture `captureSessionCheckpoint` lines358–367 reads document recovery/session state synchronously; no monitor observation may create dirty state or metadata changes. Monitor presentation should not call scheduleRecovery or onSessionChange. Only actual admitted reload/URL adoption affects persisted state.
- AppDelegate has no applicationDidBecomeActive monitor hook today. Add process-wide forced reconciliation for activation, wake/volume hints and30-second service timer per design. Observer installation/removal is service/app lifetime work, not a per-pane display action; never resolve paths or call probe from notification delivery/MainActor.

## UI and command insertion points

Window construction lines297–327 uses a vertical stack: tabBar, hidden popup tabs, languagePicker, workspaceSplit, status, checkpointStatusRow. Add a separate nonmodal document disk-status row without replacing status or checkpoint failure UI. Give real label/actions the agreed AX IDs: document.diskStatus, document.checkDisk, document.reloadDisk, document.openDiskCopy, document.locateSource. A window-level renderer reads the selected document's state; state remains document-owned when tabs switch. Both split panes share the row and never duplicate alerts/checks.

`refresh` lines2177–2204 and `updateStatus` lines2206–2238 currently call notification paths: updateStatus invokes notifySessionChange. Therefore a monitor-only status update should use a separate pure render method like existing `updateSessionCheckpointStatus` lines344–350, not generic refresh/updateStatus, avoiding checkpoint feedback and repeated status-driven disk work. Re-render selected state when display/tab selection changes, without registration/rebind.

Add `file.checkDisk` and `file.resolveDiskChange` once in AppCommands.registry; they currently do not exist. AppDelegate.dispatch line332 routes normal editor commands through the existing registry/controller path, and validateMenuItem line461 delegates to isCommandAvailable. Controller availability/action callbacks should use the same reducer admission with live state. LargeFileWindowController's whitelist currently omits these actions; do not expose editable-buffer monitor actions for the byte viewer by accidental fallback. A source-less scratch should show no file action rather than invent a URL or open an unrelated new window.

The resolve panel must capture document UUID/full accepted token and keep actions bound to that document even when activeEditor changes. Keep Buffer invokes reducer.dismiss(token:) with the captured full token; stale dismiss is rejected. Check Again must support unregistered/failed-watch tabs via bounded one-shot service API. Closing a panel cancels only that panel's pending action/read request, not the document's long-lived watch. Ordinary watcher signals never open modal dialogs.

## Required boundary regressions before native integration claims

1. Successful open/session-file restore/reopened closed tab registers once; duplicate open/split/focus/collapse does not; scratch/backup/recovery never registers. Closed retained history releases registration despite live object retention.
2. Save snapshot busy deferral, own atomic replacement then external replacement, failed Save As, uncertain different destination, and exact retry preserve acknowledged authority; matching watch bytes cannot clear pending evidence/recovery.
3. Old callback after rebind/close/quit/newer request rejected from live context; one-shot129th tab works, setup/capacity errors remain actionable; cancellation does not await blocked probe I/O.
4. Reload A while focus changes to B; recording starts during async/modal interval; composition/direct callback bypass; permission/decode/identity failure; second disk change during confirmation; all retain correct buffers/undo/focus on failure.
5. BOM LE→BE and legacy→UTF8-BOM, BOM-less legacy fallback, unsupported UTF32 rejection, explicit encoding reopen unchanged; each successful pane selection scalar-safe, axis/pane identity retained.
6. Status render alone causes no checkpoint/recovery/monitor registration or repeated alert. Locate same bytes updates URL/MRU/session once, changed bytes cannot silently rebind, uncertainty cannot redirect, disk-copy stays scratch.

This map does not authorize replacing any existing save/conflict/undo/lifecycle guarantee with a watcher hint. Registration and action APIs still need root-owned integration and real callback tests; service-only success is insufficient.
