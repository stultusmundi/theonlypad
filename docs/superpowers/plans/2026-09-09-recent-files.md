# Recent files integration

Planned: a single file.recent registry command opens an AppKit table with Open (Return/double-click), Remove From List and Clear List. Missing file failures retain history. All actions operate on path metadata; none deletes files. Opens reuse EditorWindowController.open, including its existing dirty-buffer fast path, with a validity callback checked before asynchronous results change the target window. The panel disables reentrant actions and invalidates pending opens on close, selection change or list replacement.

History records only successful user opens, never session restoration. Keep the most recent 50 distinct standardized local paths. Merge early successful opens ahead of loaded session history. Persistence uses SessionStore at successful quit; debounced autosave remains separate.

TDD: real temporary history store and text files; MRU ordering/cap/dedup, load-race merge, remove/clear persistence, missing-file retention, native actions, closed/list-changed/selection-changed callbacks and failed target guards. Physical keyboard and packaged acceptance remain separate.

Implemented: native panel and central registry command; MRU metadata update after successful user opens across the shared editor entry point. Loaded history merges behind early successful opens. Remove/Clear affect history only; existing SessionStore persists it at quit. The panel reuses the editor's open pipeline and passes its generation/selection validity callback; an already-open dirty buffer is selected without reading or replacing it. Closed or frozen targets, stale asynchronous reads and encoding reload failures complete with an error exactly once. Successful encoding reopen invokes the history callback; session restoration does not. Missing paths stay listed with their error.

Tested in isolation: expected missing APIs were observed before implementation. RecentFilesHarness passed real temporary SessionStore persistence, MRU order/dedup/cap, early-open merge, invalid URL rejection, missing-file retention, native Return-key opening, removal/clear without file deletion, and stale selection/list/close guards. RecentFilesEditorHarness passed actual editor callbacks, existing dirty buffer after file deletion, concurrent opens preserving intervening edits, rejected/frozen/closed requests, explicit >100MB failure without false MRU success, encoding reload read failure/cancellation/success, and native Cancel-discard preserving dirty text. Native source compile was warning-free after labeling older trailing closures.

Scope limits: recent-panel opens above 100 MB report an actionable error until byte-viewer successful-load completion is available. Ordinary Open still routes large files to the byte viewer, but constructing its window does not claim successful text-open history. History persists at quit; debounced metadata persistence is not implemented here. Physical keyboard interaction and packaged Recent Files acceptance remain separate from synthetic AppKit event/callback evidence.
