# Private versioned session metadata

Own SessionStore.swift/models, tests and plan. Develop isolated; coordinate before copying green files to main. No editor/menu/startup changes. Current schema v1; reject future versions unchanged. No fictional prior schema or migration claim; migrations follow real persisted versions later.

EditorSession contains ordered SessionWindow values (stable UUID, ordered tabs, selectedTabID). SessionTab contains stable UUID, optional originalPath, pinned flag, saved-byte encoding, optional manual language, UTF16 selection and bookmark offsets. Scratch/dirty text remains RecoveryStore data joined by document UUID. Preserve all order and metadata; do not normalize/reorder tabs or silently discard invalid records. EditorSession also preserves up to 50 distinct recentPaths in order using the same local-path validation. Empty recentPaths is omitted in the v1 envelope and defaults to an empty array when absent. Cap 32 windows/128 total tabs/10,000 bookmarks per tab; all document/window IDs unique, selected IDs belong to the corresponding window. Empty windows use nil selected ID. Selections/marks bounded to 100 million UTF16 units with safe integer arithmetic. Mark offsets sorted and unique.

Selection bounds here are metadata bounds, not proof of scalar boundaries or bookmark line starts. The root must check actual loaded text and preserve unresolved sessions if files are missing/renamed. Never search guessed paths or open referenced documents from this core. originalPath accepts canonical absolute local-path metadata up to 4096 UTF8 bytes, no NUL/remote URL. Encoding describes original saved bytes; recovery overrides dirty text/current encoding on restoration. Missing paths remain intact in session metadata.

Private 0700 directory and 0600 Session.json, owner and nofollow regular-file checks, bounded exact reads (16MiB envelope). Canonical JSON v1 schema rejects unknown/duplicate/noncanonical fields. Atomic write uses private owned temp file, sync and rename in pinned directory; only this call's temp is cleaned on failure. Advisory directory lock plus process lock serializes writers. Existing corrupt/future-version state blocks replacement and stays untouched. Post-publication sync error is distinguishable from pre-write refusal. Diagnostics contain no private paths. Crashed staging files are uncommitted artifacts, never interpreted as session records or automatically swept.

## Safety boundaries

The process lock and advisory directory lock coordinate cooperating stores. Directory descriptors and nofollow final components prevent redirecting reads/publication via a replaced final symlink. This is not a protection boundary against an actively malicious process running as the same user that ignores locks and races the final check/rename. No file contents are stored here; recovery remains separate. No automatic cleanup deletes corrupt state or crash-stage artifacts. Missing/renamed original paths remain metadata for an explicit restoration decision. Selection scalar boundaries and bookmark line starts must be revalidated against actual decoded document text on load; metadata validation cannot prove either. Root must merge recovery by UUID before deciding which saved content or scratch buffers to display.
