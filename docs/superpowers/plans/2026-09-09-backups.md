# Private backup records

Develop isolated under .local/backup-spike; notify root before copying exact green owned source/tests/plan. Root owns normal-save integration. No backups are automatically captured by this service alone.

Single canonical JSON envelope contains schema version, UUID, standardized original path metadata, epoch timestamp, byte count, SHA256 and base64 bytes. Per-record limit 100MB, aggregate decoded data 500MB, 100 records; caller may lower these bounds. Encoding expansion and one-record decode temporary memory are bounded but exceed raw size; no streaming-memory guarantee. No separate index. Root supplies original loaded bytes before attempting a normal save; read returns exact verified bytes for restoration to a new destination, never overwriting source paths itself.

Private 0700 directory, 0600 regular single-link files, owner validation and nofollow fd-relative I/O. In-process lock plus advisory directory flock coordinates store calls. Capture writes a UUID.pending record, fsyncs, then exclusive atomic rename to UUID.json and directory fsync. Before publication failure removes only that capture's pending file. A crashed pending record is reported explicitly, not ignored or auto-deleted. Post-publication durability failure must be reported as committed-but-not-synced with record ID. list validates all records and hashes; capture fails if any existing record is corrupt/incomplete. read validates selected record. remove explicitly removes matching UUID final/pending records, including malformed bytes, never unrelated entries.

Strict canonical re-encoding rejects unknown/duplicate/missing fields, malformed base64, noncanonical values and whitespace edits. Timestamp/path/id/size/digest validated. Original private paths are metadata only; diagnostic errors contain at most UUID, never paths or raw underlying NSError payloads. Unexpected filenames, symlinks, insecure ownership/permissions and malformed records are explicit failures. Directory and read-file identity checked. Advisory locks cannot stop arbitrary same-user filesystem writers; metadata checks do not claim immutable hostile-writer snapshots.

Public capture includes `encoding: DocumentEncoding = .utf8`. BackupRecord includes encoding. `snapshot(id:)` returns one verified envelope's BackupRecord and Data together, preventing a controller from pairing cached encoding metadata with newly read bytes. Root must pass savedEncoding of original loaded bytes, not the new encoding chosen for the next save. The service never writes originalPath.

Native manager supports a directory argument for isolated synthetic testing and `onRestore: @MainActor (BackupRecord, Data) async throws -> Void`. It lists original paths/date/size/encoding, restores a verified snapshot, and confirms UUID-scoped deletion. On corrupt/incomplete errors the record UUID is prefilled for manual removal. Unexpected nonrecord entries and unsafe permissions require manual filesystem correction; the manager never deletes unrelated entries. Closing invalidates asynchronous UI callbacks but does not interrupt bounded in-flight filesystem work.

## Integrated verification

Backup failure leaves the original untouched and the editor dirty/editable. Restore decodes off-main, checks window/quit lifecycle, and creates a new scratch tab with original encoding/BOM. Restore errors propagate into the manager status.
