## Recommended order and shared boundary

First reproduce `replaceDocumentText` with an actual native delegate that changes same-length text after its initial snapshot checks. Then extract the reviewed search commit path into one private, synchronous `applyNativeTextEdit(document:source:expected:edit:action:...) -> Bool` inside EditorWindowController. Migrate search to it in the same small step, retaining all12 search assertions as integration controls. The helper owns exact target validation, outer-invocation claim, staged bookmark/macro bookkeeping, coalescing boundary, balanced native undo group, final callback/primitive checks, commit and didChange. It returns whether bytes were applied; focus/selection/scrolling, async work and operation completion remain in callers.

Use the existing TextEdit value for the actual native range/replacement. Do not convert partial edits to whole-document replacements or change action names merely to share code. Generalize `SearchReplacementPreparation` to a private edit preparation name only after caller RED. Its no-op test currently compares the whole storage to the replacement; that must become exact equality of the affected UTF16 slice to the replacement before partial edits adopt it. Validate nonnegative range, overflow-safe end, bounds and surrogate-safe endpoints against the exact expected native UTF16 snapshot. Reuse reviewed native-boundary semantics; do not accidentally impose a new grapheme-boundary restriction on scalar-safe TextDifference edits. Avoid constructing another whole result String just to validate a tiny edit.

Separate callback-capable admission from final primitive validation. Every admission closure may reenter, so it must run before snapshot/selection/operation/cancellation rechecks. A final `accepts(context)` call alone is not a primitive fence because it calls applicationAllows. Do not call a generic caller callback after the final primitive check and then write. The token must be claimed at outer delegate entry before mayMutate exactly as the current12-case proof requires; nested edits with identical arguments retain normal bookkeeping.

Capture revision, ownership, close-mutation generation, exact source/storage identity and reject pending editedCharacters. Partial-edit proposal snapshots must preserve existing pending/no-op bookmark semantics and macro range/replacement/limit behavior. No undo removal, guessed rollback or changed model authority. Native text-storage notification reentrancy during the actual mutation remains distinct from the tested precommit callback boundaries; do not claim generalized atomicity.

## Scope, design alternatives and unresolved gates

Copying the guard into four routes is smaller per call site but repeats the now-proven macro/bookmark hazard. Replacing all routes with whole-document search replacement changes partial-range macro/selection behavior. A shared TextEdit commit boundary preserves per-route work while centralizing the callback proof, so it is preferred. Do not alter source storage/undo architecture, other raw initialization/restoration writes, macro dialect/caps, file-operation actor ownership or user-facing format limits in this repair.

Before implementation root should review the helper API/final-predicate ordering and each route's observable RED plan. Public claims remain limited to routes actually migrated and tested. GUI/physical input, IME, large-file/input latency and the broader editor-engine concerns remain separate acceptance work.
