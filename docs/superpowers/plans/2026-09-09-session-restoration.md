# Session restoration planning

Implement a pure merge of already decoded session metadata and validated recovery snapshots. No referenced file I/O and no document writes. Retain existing window/tab order, selection, pinning, language and bookmark metadata. Matching recovery wins as scratch; original paths are informational and never overwrite destinations. Saved paths lacking recovery become explicit file-load requests; scratch entries lacking recovery become missingRecovery, never invented empty text. Orphans retain input order in one additional window. Reject duplicates and ID collisions explicitly. Typed UUIDs exclude malformed textual identifiers at this layer; store decoders reject malformed serialized UUIDs.

Bound combined output to 256 tabs, original windows to 32 and optional orphan window to one. Overlimits throw before returning partial output. Returned plan exposes missing recovery IDs and persistence overcapacity (128 tabs or 32 windows); root must resolve this explicitly before saving via SessionStore. No invented schema migration. Referenced files may be missing or renamed; later loading must report each failure, validate actual scalar selections and line-start bookmarks, and never silently remove unresolved entries.

TDD isolated: matching recovery precedence and metadata, missing recovery versus file requests, ordered orphan/new initial session, duplicate IDs, invalid selected IDs, combined caps and preservation beyond persistence limits. Caller-provided orphanWindowID allows deterministic output; default UUID is convenient when a new window is needed. Implemented in isolation; native startup restoration remains outstanding.

The planner rechecks total recovery text <=100 million UTF16 units and recovery path metadata <=4096 units, plus bounded session selections/bookmarks/paths. Recovery text/encoding/BOM always come from the snapshot, even when informational SessionTab encoding/path differ. `.file` always carries saved-byte tab encoding. Unknown/missing files are requests, not successful restoration claims.

`needsResolution` specifically flags known missing scratch recovery or persistence overcapacity; it does not certify file existence or actual-text position validity. Root must validate every file-load result before navigating. A result above SessionStore's 128-tab/32-window cap must be resolved explicitly before persistence; do not save a truncated subset. Errors return no partial result and never mutate inputs or delete recovery records.
