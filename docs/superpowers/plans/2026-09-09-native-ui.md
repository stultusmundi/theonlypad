# Native document UI execution plan

Status: planned, implementation in progress. GUI acceptance unverified.

Ownership: EditorWindowController.swift (including private document/view types). Other agents own core and app wiring.

1. Construct explicit TextKit 1 editor per tab with separate native undo manager, plain text, monospaced font, native find bar, wrap and status.
2. Route new/open/save/save-as/close and line transforms through `execute`; preserve original bytes and codec metadata. Perform file I/O and encoding in detached tasks.
3. Reject inputs over 100 MB before loading; bound reads to limit + 1. Prevent edits and close during save, preserve URL/baseline on failure, and confirm discard for dirty closes/reloads.
4. Build using `scripts/swift.sh build`; exercise synthetic adapter operations in an executable harness if desktop session permits. Core agents cover codec/store/transforms with unit tests. No UI claim based solely on compilation.

Public integration: `@MainActor EditorWindowController: NSWindowController, NSWindowDelegate`; `init()`, `newDocument()`, `open(_:)`, `execute(_:)`, `onClose`. Each window starts with one scratch document. Commands: file.new/open/save/saveAs/saveAll/close/reload; edit.* LineTransform raw values; view.wrap; edit.find.

Acceptance outstanding: real native dialogs, keyboard/find interactions, dirty tab and window close, Save As overwrite/cancel, I/O failures, undo after tab switching, concurrent save/close. Recovery/session restoration, tab reordering/pinning, and large-file bounded viewer remain outstanding; no placeholder controls added.

## Recovery integration plan — in progress

Introduce a serial `RecoveryCoordinator` actor, defaulting to Application Support/org.theonlypad.editor/Recovery. `THEONLYPAD_STATE_DIRECTORY` overrides the directory only when explicitly supplied for synthetic tests. Startup snapshots are claimed once per app and restored as scratch buffers, never linked to their original path for Save. Persist dirty/scratch buffers after a debounce, flush on orderly quit, and remove snapshots for explicit discard. Revisions plus permanent closed-ID tombstones prevent out-of-order snapshots resurrecting closed buffers. Report snapshot failures and quarantined corrupt files.

Root integration: `prepareToQuit() async -> Bool` freezes document mutation and flushes recovery; `cancelPreparedQuit()` unlocks if another window vetoes. Application delegate uses `.terminateLater`, awaits every controller, then replies to AppKit. `canClose()` remains explicit window-close/discard policy.

Regression targets: a late queued update after close cannot recreate snapshot; stale lower revision cannot overwrite newer snapshot; fresh coordinator restores from disk; corrupt quarantine is surfaced; process termination after a committed snapshot leaves it recoverable. UI recovery acceptance remains separate from actor/store tests.

## Recovery and language integration evidence

Implemented: RecoveryCoordinator serial actor; revision ordering; closed-document tombstones; 750 ms debounce plus 15-second periodic snapshot interval; scratch/dirty recovery; once-per-app startup restoration as safe scratch; corrupt quarantine warnings; async quit flush with mutation lock; static `finishPendingCloses() async -> Bool` drains explicit-close cleanup even when the last window has closed. Root termination must await this static method before replying to AppKit. `THEONLYPAD_STATE_DIRECTORY` is used by tests to isolate synthetic documents. Default storage uses `AppIdentity.bundleIdentifier` under Application Support.

Independent review fixes included: dirty/no-op checks compare exact UTF-16 sequences so canonical-equivalent normalization changes remain edits. Save As is create-only: existing files and targets created after the save panel are refused; this prevents a detached task treating a later file as a consented overwrite. Existing-path Save retains the original byte baseline. A confirmed Save As replacement flow remains outstanding.

Language integration: per-document lexical highlighter with manual language picker and plain-text option; filename/shebang detection; explicit highlighting-disabled status above two million UTF-16 units; asynchronous JSON formatting with exact captured-text validation and one native undo transaction. Syntax highlighting is lexical assistance, not semantic intelligence or incremental parsing.

Reproducible tracked verification:

```sh
scripts/test-native-integration.sh
```

This builds and runs `Tests/NativeIntegration/RecoveryHarness.swift` and `NativeUIHarness.swift` against production AppKit controller sources. Tests use a generated private synthetic fixture directory and remove it on exit. The recovery child is deliberately killed with SIGKILL **after** verifying its debounced snapshot is committed, then a new process restores the exact text as scratch. This proves committed-snapshot recovery across process death, not zero-loss recovery for input since the last snapshot. The command passed, including the exact-normalization dirty and JSON-format undo assertions. Native panel interactions and external accessibility/keyboard automation remain unverified.

Recovery scope still outstanding: clean-file tab/session layout restoration, per-window placement, guaranteed capture of edits after the last snapshot, snapshot size/quota management, multi-process application coordination, and comprehensive recovery failure UX tests. The 15-second interval bounds scheduling under continuous typing; it is not a guaranteed deadline when the process or disk is stalled.

Final controller settings integration: `applySettings(_ settings: EditorSettings)` validates the settings and applies font, wrap, and paragraph tab intervals to every existing document; later new/open/restored documents inherit current settings. App-wide appearance remains AppDelegate's responsibility. Native integration assertions now verify manual Swift display attributes/plain-text clearing without changing document bytes, close cleanup removing committed scratch snapshots, and font/wrap/tab inheritance.
