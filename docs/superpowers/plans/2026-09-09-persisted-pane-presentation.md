# Persisted Document Pane Presentation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task by task with independent review at each ownership boundary.

**Goal:** Reopen split axis, per-pane selection/scroll and preferred pane with one logical document identity.

**Architecture:** Versioned Session v2 embeds bounded presentation metadata per tab. MainActor capture pairs it with existing recovery capture; off-main startup validation precedes native installation; bounded live-range revalidation is synchronous without text copies. Lazy presentation preserves inactive state without activating windows.

**Tech Stack:** Swift 5 language mode, macOS 14+, Foundation/AppKit/TextKit1, existing private stores and checkpoint scheduler, no dependencies.

**Spec:** [persisted-pane-presentation.md](../specs/persisted-pane-presentation.md). Status: core Tasks 1–2 implemented and tested; native integration/review and desktop acceptance remain open. See docs/verification/persisted-pane-presentation.md for actual evidence.

## Global constraints

- Preserve exact source bytes/UTF16, undo, composition, saved baseline, pending publication and one recovery UUID per document.
- Existing canonical v1 data migrates in memory; v0 and future versions fail unchanged. No load-time rewrite.
- Current 100M UTF16 view-state bound, 2M split admission, 16MiB session envelope, 32-window/128-persisted-tab and existing recovery/orphan bounds remain unchanged.
- Public tracked artifacts contain synthetic fixtures only. Raw evidence stays ignored. No GUI execution while screen locked.
- Do not edit files assigned to another worker. Coordinate source copies and native build slots; commits are scoped after review, not automatic publication.
